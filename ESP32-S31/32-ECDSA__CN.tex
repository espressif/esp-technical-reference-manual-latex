\section{概述}

在密码学中，椭圆曲线数字签名算法 (ECDSA) 是数字签名算法 (DSA) 基于椭圆曲线密码学的一种变体。

\chipname{} 的 ECDSA 数字签名外设 (ECDSA\_DS) 可在安全高效的环境中计算 ECDSA 签名，不仅可保证签名过程的机密性，还实现了快速计算，非常适合对加密安全性和加密速度有高要求的应用。通过 ECDSA\_DS 模块，用户可以在不牺牲性能的情况下保证数据得到保护。

\section{主要特性}
\label{sec:ecdsa-features}

\chipname{} 的 ECDSA\_DS 模块支持：

\begin{itemize}
    \item 数字签名的生成和验证
    \item 四种椭圆曲线，分别是 P-192、P-256 和 P-384（具体定义见 \href{https://nvlpubs.nist.gov/nistpubs/FIPS/NIST.FIPS.186-5.pdf}{FIPS 186-5 规范}），以及 SM2（具体定义见 \href{http://www.gmbz.org.cn/file/2018-01-08/f60d13a3-e0fd-40d8-a80f-13fde691ef03.pdf}{GM/T 0003.2-2012 规范}）
    \item 用于 ECDSA\_DS 运算的多种消息哈希算法，包括 SHA-224、SHA-256、SHA-384、SHA-512、SHA-512-224 和 SHA-512-256（具体定义见 \href{https://doi.org/10.6028/NIST.FIPS.180-4}{FIPS PUB 180-4 规范}），以及 SM3（具体定义见 \href{http://www.gmbz.org.cn/file/2018-01-08/6db059ec-61e1-4ff9-b112-ae15471ad6b5.PDF}{GM/T 0004-2012 规范}）
    \item 基于不同工作状态的寄存器访问控制，以确保信息安全
\end{itemize}

\section{ECDSA 背景知识}
\subsection{域参数}

ECDSA 使用的参数通常被称为域参数，可用于生成密钥、生成签名和验证签名等运算，主要包括有限域中定义的椭圆曲线参数、曲线上的基点和基点阶数等。

ECDSA 使用的域参数主要包括两大类：

\begin{itemize}
    \item 椭圆曲线域参数：
          \begin{itemize}
              \item 质数模数 $p$，指定定义椭圆曲线的有限域的大小。
              \item 系数 $a$ 和 $b$，用于指定椭圆曲线方程。
              \item 曲线上的基点 $G$，用于生成公钥。
              \item 基点的阶数 $n$，代表在椭圆曲线上对基点 $G$ 进行重复点加的次数。
          \end{itemize}
    \item 哈希函数参数：
          \begin{itemize}
              \item 哈希算法，用于从待签名的消息生成固定长度的哈希值。
              \item 哈希值的长度，决定签名的大小。
          \end{itemize}
\end{itemize}

这些参数共同定义了 ECDSA 域。

\subsection{密钥生成}

ECDSA 中的密钥生成过程如下所述：

\begin{enumerate}
    \item 选择一个椭圆曲线域，定义如下参数：
    \begin{itemize}
        \item 质数模数 $p$
        \item 系数 $a$ 和 $b$
        \item 基点 $G$ 和其阶数 $n$
    \end{itemize}
    \item 生成私钥：
    \begin{itemize}
        \item 私钥 $d$ 为在 1 到 $n$-1 之间随机选择的整数。注意，必须确保私钥是真正随机的，应当不可预测或不可重现，因此，使用安全的 \nameref{mod:rng} 非常重要。
        \item 私钥用于生成签名，需妥善保密保管。
        \item 私钥选择完成后，应将其烧录到 \chipname{} 的 eFuse 中（参考章节 \ref{mod:efuse} \textit{\nameref{mod:efuse}}）。
    \end{itemize}
    \item 计算公钥：
    \begin{itemize}
        \item 公钥 $Q$ 的计算方式为 $Q = dG$。
    \end{itemize}
    \item 导出公钥：
    \begin{itemize}
        \item 公钥 $Q$ 通常以 ($Qx$，$Qy$) 表示，可公开给他人。
    \end{itemize}
\end{enumerate}

\subsection{签名生成}

ECDSA 签名生成过程如下所述：

\begin{enumerate}
    \item 选择一条消息 $m$，用于签名。
    \item 计算消息 $m$ 的哈希值 $e$：$e$ = HASH(m)，其中 HASH 是一个密码学哈希函数，例如 SHA-256。
    \item 计算消息哈希值 $e$ 的摘要 $z$：令 $z$ 为 $e$ 的左端 $L_n$ 位，其中 $L_n$ 是基点阶数 $n$ 的位长度。
    \item 选择一个随机数 $k$：范围在 1 到 $n$-1 之间，其中 $n$ 是椭圆曲线上基点的阶数。
    \item 计算签名：签名计算如下：
          \begin{enumerate}
              \item 计算点 ($x$, $y$) = $kG$
              \item 计算 $r$ = $x$ \textrm{mod} $n$。如果 $r$ 等于零，返回上一步并选择新的 $k$ 值。
              \item 计算 $s$ = $k$$^{-1}$ * $(z + d*r)$ \textrm{mod} $n$。如果 $s$ 等于零，返回步骤 4 并选择新的 $k$ 值。
              \item 签名为 ($r$, $s$)。
          \end{enumerate}
    \item 发送消息 $m$ 和签名 ($r$, $s$) 给接收者。
\end{enumerate}

\subsection{签名验证}

接收方可以使用密钥生成阶段导出的公钥，来验证对应私钥生成的签名。验证过程涉及检查签名是否由对应的私钥生成，以及签名是否对给定的消息有效。

ECDSA 签名验证过程如下所述：

\begin{enumerate}
    \item 获得公钥 $Q$，接收消息 $m$ 和签名 ($r$, $s$)。
    \item 计算消息的哈希值：$e$ 等于 HASH(m)，其中 HASH 是一个密码学哈希函数，例如 SHA-256。
    \item 计算消息的摘要：令 $z$ 为 $e$ 的左端 $L_n$ 位，其中 $L_n$ 是基点阶数 $n$ 的位长度。
    \item 验证签名：签名验证如下所示：
        \begin{enumerate}
            \item 验证 $r$ 和 $s$ 是否是介于 1 到 $n$-1 之间的整数，其中 $n$ 是椭圆曲线上基点的阶数。如果 $r$ 或 $s$ 超出此范围，则签名无效。
            \item 计算 $u_1 = z * s^{-1}$ \textrm{mod} $n$ 和 $u_2 = r * s^{-1}$ \textrm{mod} $n$。
            \item 计算点 $(x_1, y_1) = u_1 * G + u_2 * Q$，其中 $G$ 是椭圆曲线上的基点，$Q$ 是与用于签名生成的私钥相关联的公钥。
            \item 验证 $r = x_1$ \textrm{mod} $n$。如果 $r$ 不等于 $x_1$ \textrm{mod} $n$，则签名无效。
        \end{enumerate}
    \item 接受或拒绝签名：如果签名有效，接收方可以确信消息没有被篡改，且消息来自预期的发送方，可以接收。否则，接收方将拒绝并判定为无效消息。
\end{enumerate}

\subsection{密钥来源}

\chipname{} 的 ECDSA\_DS 模块可以使用硬件部署的密钥或软件编程的密钥。硬件部署的密钥可以来自 eFuse（参考章节 \ref{mod:efuse} \textit{\nameref{mod:efuse}}）或密钥管理器（参考章节 \ref{mod:keymng} \textit{\nameref{mod:keymng}}）。如果使用软件编程的密钥，需要将密钥分成 32 位的数据块，并写入 \hyperref[regdesc:ECDSADSKEY0REG]{ECDSA\_DS\_KEY\_\regindex{n}\_REG}（\regindex{n} = 0 \verb+~+ 11）。在配置时，应将 \hyperref[fielddesc:ECDSADSUSEHARDWAREKEY]{ECDSA\_DS\_USE\_HARDWARE\_KEY} 设置为 0，以使 ECDSA\_DS 使用软件编程的密钥。

\subsection{数据和数据块}

\chipname{} 的 ECDSA\_DS 会用到的数据位宽为 192、256、384 或 512 位。

假设一个数据为 $D[255:0]$，则其可以被划分为八个 32 位的数据块 $D[n][31:0](n=0,1,\cdots,7)$，序号较小的数据块对应数据低位。以 256 位的数据为例：
\[
D[255:0] = {D[7][31:0],D[6][31:0],D[5][31:0],
D[4][31:0],D[3][31:0],D[2][31:0],D[1][31:0],D[0][31:0]}
\]

\subsubsection{数据写入}

数据写入即将数据写入到 ECDSA\_DS 内存块的过程，该数据为 ECDSA\_DS 的输入数据。具体而言，将数据写入 ECDSA\_DS 内存块相当于将该数据 $D[n][31:0]$ 依次写入“该内存块起始地址 + $4 \times n$”。

以 256 位的数据为例：

\begin{itemize}
    \item 将 $D[0]$ 写入“起始地址”
    \item 将 $D[1]$ 写入“起始地址 + 4”
    \item $\cdots$
    \item 将 $D[7]$ 写入“起始地址 + 28”
\end{itemize}

\begin{tiplisting}
进行数据写入操作时，只需写入所需长度的数据块，无需在高位补 0。例如，写入 192 位数据时，只需存储 192 位即可。
\end{tiplisting}

\subsubsection{数据读取}

数据读取即从 ECDSA\_DS 内存块中读出数据的过程，该数据为 ECDSA\_DS 的输出数据。具体来说，从 ECDSA\_DS 内存块中读取数据相当于从“该内存块起始地址 + $4 \times n$”依次读出 $D[n][31:0]$。
以 256 位的数据为例：
\begin{itemize}
    \item 从“起始地址”读出 $D[0]$
    \item 从“起始地址 + 4”读出 $D[1]$
    \item $\cdots$
    \item 从“起始地址 + 28”读出 $D[7]$
\end{itemize}

\begin{tiplisting}
进行数据读取操作时，只需读取所需长度的数据块。例如，读取 192 位数据时，只需读取低 192 位（即 6 个数据块）。
\end{tiplisting}

\subsubsection{消息填充}\label{sec:ecdsa-msg-padding}

SHA 加速器仅能处理 512 位的消息块。因此，所有消息在进行哈希运算前，应通过软件填充至 512 位的整数倍。

假设待处理消息 \begin{math} M \end{math} 的长度为 \begin{math}L_M\end{math} 位，则填充步骤如下：

\begin{enumerate}
    \item 首先，在消息末尾填充 1 个 ``1"；
    \item 随后，再填充 \begin{math}L_A\end{math} 个 ``0"。其中，\begin{math}L_A\end{math} 为满足 \begin{math} L_M + 1 + L_A \ {\equiv} \ 448 \ mod \end{math} 512 的最小非负数解；
    \item 最后，在末尾填充一个 64 位的信息块。该信息块的内容为用二进制表示的消息的长度，即 \begin{math}L_M\end{math} 的值。
\end{enumerate}

更多详情，请参考 \href{https://doi.org/10.6028/NIST.FIPS.180-4}{《FIPS PUB 180-4 规范》}> 章节 ``Padding the Message"。

\subsubsection{解析消息}\label{sec:ecdsa-msg-parsing}

完成消息填充后，还需将消息（及其填充）解析为 \begin{math}N\end{math} 个 512 位的消息块，即 \begin{math}M^{(1)}\end{math}、\begin{math}M^{(2)}\end{math}、 \dots、\begin{math}M^{(N)}\end{math}。

\begin{tiplisting}
\begin{enumerate}
\vspace{-2.5em}
    \item 有关“解析消息”的详细信息，请参考 \href{https://doi.org/10.6028/NIST.FIPS.180-4}{FIPS PUB 180-4 规范} > 章节 ``Parsing the Message"。
    \item 有关"消息块"及相关概念的描述，请参考 \href{https://doi.org/10.6028/NIST.FIPS.180-4}{FIPS PUB 180-4 规范} > 章节 ``Glossary of Terms and Acronyms"。
\end{enumerate}
\end{tiplisting}

\subsection{安全功能}
\label{sec:ecdsa-security_features}

为确保运算过程的安全性，ECDSA\_DS 模块实现了多种安全功能。

\subsubsection{抗攻击性能}

\chipseries{} 的 ECDSA\_DS 模块每次执行操作时，都会利用 ECC 加速器的强抗攻击性能（参考小节 \ref{sec:ecc-anti-attack} \textit{\nameref{sec:ecc-anti-attack}}）。这意味着 ECDSA\_DS 在每次生成和验证签名时：

\begin{itemize}
    \item 对于给定操作，执行延迟保持恒定。
    \item 功耗波动最小化。
\end{itemize}

这为 \chipseries{} 的 ECDSA\_DS 模块提供了强大的抗攻击性能。

\subsubsection{基于状态的寄存器访问控制}

\chipseries{} 的 ECDSA\_DS 模块实施了基于状态的寄存器访问控制，可有效防止运算过程中可能发生的非法配置篡改或数据访问，从而保证密钥的安全性。

具体来说，ECDSA\_DS 的寄存器在不同工作状态下的访问权限是不同的。例如，\hyperref[regdesc:ECDSADSCONFREG]{ECDSA\_DS\_CONF\_REG} 寄存器仅在 ECDSA\_DS 处于 IDLE 状态时允许读写操作。因此，当 ECDSA\_DS 处于其他状态（如 LOAD、GAIN 和 BUSY）时，该寄存器中的配置信息则不允许读取或写入，从而得到很好的保护。有关 ECDSA\_DS 所有工作状态的详细信息，请见表 \ref{tab:ecdsa-working-state}。

有关基于状态的 ECDSA\_DS 寄存器访问控制的详细信息，请参阅\hyperref[sec:ecdsa-reg-summ]{寄存器列表}。

\subsubsection{硬件占用}

在运算过程中，ECDSA\_DS 将占用以下硬件模块：

\begin{itemize}
    \item SHA 加速器
    \item ECC 加速器
\end{itemize}

每个加速器都有一个对应的 free 字段（\hyperref[fielddesc:SHAFREE]{SHA\_FREE} 和 \hyperref[fielddesc:ECCMULTFREE]{ECC\_MULT\_FREE}），用于指示 ECDSA\_DS 是否可以立即占用该加速器。如果 free 字段设置为 1，ECDSA\_DS 在开始运算时会立即复位该加速器。如果 free 字段设置为 0，ECDSA\_DS 将等待该加速器完成当前运算，或等到 \hyperref[fielddesc:ECDSADSTIMEOUTLIMIT]{ECDSA\_DS\_TIMEOUT\_LIMIT} 设置的超时上限。

当 ECDSA\_DS 开始运算并占用加速器后，各加速器的释放方式如下：当 \hyperref[int:ECDSADSSHARELEASEINT]{ECDSA\_DS\_SHA\_RELEASE\_INT} 触发时，SHA 加速器将被释放；而 ECC 加速器在整个 ECDSA\_DS 运算期间保持占用。

如果 ECDSA\_DS 在占用一个或多个硬件加速器期间接收到外部复位，该复位也会同步传播至这些加速器。该机制确保暂存在这些加速器内部的中间结果会被清除，从而防止其因外部复位攻击而发生泄漏。

\begin{tiplisting}
硬件占用是一种保护复用模块和存储空间的机制。当一个模块被硬件占用时，用户将无法执行以下操作：
\vspace{-0.5em}
\begin{itemize}
    \item 读取或写入模块的寄存器或存储器数据。
    \item 关闭模块时钟。
    \item 复位模块。
\end{itemize}
\vspace{-0.5em}
在硬件占用结束时，占用的模块将自动复位。此外，当用户对主模块执行软件复位时，所有占用的模块将同时复位。
\end{tiplisting}

\begin{importantlisting}
\vspace{-0.5em}
\chipname{} 的 \nameref{mod:sdc} 模块在工作时也会使用 ECDSA\_DS。默认情况下，\hyperref[fielddesc:ECDSADSFREE]{ECDSA\_DS\_FREE}（值为 1）允许 \nameref{mod:sdc} 立即复位任何正在进行的 ECDSA\_DS 运算并占用 ECDSA\_DS。为防止这种行为，请将 \hyperref[fielddesc:ECDSADSFREE]{ECDSA\_DS\_FREE} 设置为 0。
\end{importantlisting}

\section{配置流程}
\label{sec:ecdsa-prog-procedures}

\subsection{ECDSA\_DS 流程}
ECDSA\_DS 的完整工作流程包括以下六个阶段。

\begin{figure}[H]
\includegraphics[width=0.5\textwidth]{\modulefiles/figures/ecdsa-stage-changes.pdf}
\centering
\caption{ECDSA\_DS 流程}
\end{figure}

每个阶段的详细配置流程在下文中描述。

\subsubsection{IDLE 阶段}
在 IDLE 阶段：
\begin{enumerate}
	\item 配置静态参数，包括 eFuse 位：
	      \begin{enumerate}
		      \item ECDSA\_KEY：ECDSA\_DS 中的私钥 $d$ 的值。请选择以下密钥来源之一：
                \begin{enumerate}
                    \item eFuse：将密钥值写入 KEY\regindex{n}（\regindex{n} = 0 \verb+~+ 5），并将相应的 \hyperref[regdesc:EFUSEKEYPURPOSE0]{EFUSE\_KEY\_PURPOSE\_\regindex{n}} 设置为 ECDSA\_KEY。有关更详细的配置步骤，请参阅章节 \ref{mod:efuse} \textit{\nameref{mod:efuse}}。
                    \item 密钥管理器：使用密钥管理器的其中一种模式为 ECDSA 部署密钥。详细的配置步骤，请参阅章节 \ref{mod:keymng} \textit{\nameref{mod:keymng}}。
                    \item ECDSA 软件寄存器：在 \hyperref[sec:ecdsa-software-key-load-stage]{LOAD 阶段}，将密钥值写入 \hyperref[regdesc:ECDSADSKEY0REG]{ECDSA\_DS\_KEY\_\regindex{n}\_REG}（\regindex{n} = 0 \verb+~+ 11）。
               \end{enumerate}
	      \end{enumerate}
	\item 配置 \hyperref[regdesc:ECDSADSCONFREG]{ECDSA\_DS\_CONF\_REG}，包括以下字段：
	      \begin{enumerate}
		      \item \hyperref[fielddesc:ECDSADSWORKMODE]{ECDSA\_DS\_WORK\_MODE}：选择 ECDSA\_DS 的工作模式。
		      \item \hyperref[fielddesc:ECDSADSECCCURVE]{ECDSA\_DS\_ECC\_CURVE}：选择 ECDSA\_DS 的椭圆曲线。
		      \item \hyperref[fielddesc:ECDSADSSOFTWARESETZ]{ECDSA\_DS\_SOFTWARE\_SET\_Z}：选择是否使用直接输入的 $z$。
		    \item \hyperref[fielddesc:ECDSADSDETERMINISTICK]{ECDSA\_DS\_DETERMINISTIC\_K}：选择是否使用确定性的 $k$。
                \item \hyperref[fielddesc:ECDSADSUSEHARDWAREKEY]{ECDSA\_DS\_USE\_HARDWARE\_KEY}：选择 ECDSA 密钥来源是软件编程寄存器还是硬件来源（eFuse 或密钥管理器）。
	      \end{enumerate}
	\item 配置寄存器字段 \hyperref[fielddesc:ECDSADSSTART]{ECDSA\_DS\_START} 以进入 PREP 阶段。
\end{enumerate}

\begin{tiplisting}
更多有关“确定性 ECDSA” (Deterministic ECDSA) 的信息，请参考 \href{https://www.rfc-editor.org/rfc/rfc6979}{RFC6979}。
\end{tiplisting}

\subsubsection{PREP 阶段}

在 PREP 阶段，\hyperref[regdesc:ECDSADSSTATEREG]{ECDSA\_DS\_STATE\_REG} 为 BUSY，ECDSA\_DS 执行准备工作。

轮询 \hyperref[fielddesc:ECDSADSBUSY]{ECDSA\_DS\_BUSY} 直到其不为 BUSY，等待 PREP 阶段结束。然后 ECDSA\_DS 将自动进入 LOAD 阶段。

\subsubsection{LOAD 阶段}
在 LOAD 阶段：

\begin{enumerate}
	\item 使用以下选项之一将输入 $z$ 提供给 ECDSA\_DS：
	      \begin{itemize}
		      \item 直接输入 $z$：将 $z$ 写入 \hyperref[tab:ecdsa-memory]{ECDSA\_DS\_MEM\_Z}。
		      \item ECDSA\_DS SHA 接口：从消息生成 $z$。有关详细信息，请参阅第 \ref{sec:ecdsa-sha-interface} 节。
	      \end{itemize}
	\item 根据所选的 \hyperref[fielddesc:ECDSADSWORKMODE]{ECDSA\_DS\_WORK\_MODE}，进行以下配置：
	      \begin{itemize}
		      \item 签名验证：
		            \begin{enumerate}
			            \item 将签名 ($r$，$s$) 写入 \hyperref[tab:ecdsa-memory]{ECDSA\_DS\_MEM\_R} 和 \hyperref[tab:ecdsa-memory]{ECDSA\_DS\_MEM\_S}。
			            \item 将公钥 ($Qx$，$Qy$) 写入 \hyperref[tab:ecdsa-memory]{ECDSA\_DS\_MEM\_Qx} 和 \hyperref[tab:ecdsa-memory]{ECDSA\_DS\_MEM\_Qy}。
		            \end{enumerate}
		      \item 签名生成：
		            \begin{enumerate}
			            \item 不需要其他配置。
		            \end{enumerate}
                \item 公钥导出：
		            \begin{enumerate}
                            \item 不需要其他配置。
		            \end{enumerate}
	      \end{itemize}
        \item 如果使用 ECDSA 软件寄存器中的密钥，需以大端格式配置 \hyperref[regdesc:ECDSADSKEY0REG]{ECDSA\_DS\_KEY\_\regindex{n}\_REG}（\regindex{n} = 0 \verb+~+ 11）。192 位密钥使用 \regindex{n} = 0 \verb+~+ 5，256 位密钥使用 \regindex{n} = 0 \verb+~+ 7，384 位密钥使用 \regindex{n} = 0 \verb+~+ 11。例如，$Key[255:0]$ 中，$Key[255:224]$ 写入 \regindex{n} = 7，$Key[31:0]$ 写入 \regindex{n} = 0。
        \label{sec:ecdsa-software-key-load-stage}
	\item 将 1 写入 \hyperref[fielddesc:ECDSADSLOADDONE]{ECDSA\_DS\_LOAD\_DONE}，表示配置完成。然后 ECDSA\_DS 将自动进入 PROC 阶段。
\end{enumerate}

\subsubsection{PROC 阶段}

在 PROC 阶段，\hyperref[regdesc:ECDSADSSTATEREG]{ECDSA\_DS\_STATE\_REG} 为 BUSY，ECDSA\_DS 根据所选的工作模式执行运算。

通过轮询 \hyperref[regdesc:ECDSADSSTATEREG]{ECDSA\_DS\_STATE\_REG} 直到其中的 \hyperref[fielddesc:ECDSADSBUSY]{ECDSA\_DS\_BUSY} 字段指示不为 BUSY，表示 PROC 阶段已结束。然后 ECDSA\_DS 将根据所选的工作模式自动进入 GAIN 阶段或 POST 阶段：
\begin{itemize}
    \item 签名生成：GAIN 阶段
    \item 签名验证：POST 阶段
    \item 公钥导出：GAIN 阶段
\end{itemize}

\subsubsection{GAIN 阶段}

当选择了签名生成或公钥导出模式时，ECDSA\_DS 在 PROC 阶段之后进入 GAIN 阶段：

\begin{enumerate}
	\item 从 ECDSA\_DS 内存中读取数据：
	      \begin{itemize}
		      \item 从 \hyperref[tab:ecdsa-memory]{ECDSA\_DS\_MEM\_R} 和 \hyperref[tab:ecdsa-memory]{ECDSA\_DS\_MEM\_S} 读取签名 ($r$, $s$)，仅在签名生成模式下。
		      \item 从 \hyperref[tab:ecdsa-memory]{ECDSA\_DS\_MEM\_Qx} 和 \hyperref[tab:ecdsa-memory]{ECDSA\_DS\_MEM\_Qy} 读取公钥 ($Qx$, $Qy$)，在签名生成或公钥导出模式下。
	      \end{itemize}
	\item 向 \hyperref[fielddesc:ECDSADSGETDONE]{ECDSA\_DS\_GET\_DONE} 写入 1，表示 GAIN 阶段已完成。然后 ECDSA\_DS 将自动进入 POST 阶段。
\end{enumerate}

\subsubsection{POST 阶段}

在 POST 阶段，\hyperref[regdesc:ECDSADSSTATEREG]{ECDSA\_DS\_STATE\_REG} 为 BUSY，ECDSA\_DS 执行运算的收尾工作。

通过轮询 \hyperref[fielddesc:ECDSADSBUSY]{ECDSA\_DS\_BUSY} 直到不再为 BUSY，表示 POST 阶段已结束。然后 ECDSA\_DS 将自动返回 IDLE 阶段。

\subsubsection{ECDSA\_DS SHA 接口}
\label{sec:ecdsa-sha-interface}

\chipseries{} 的 ECDSA\_DS 模块可以自动执行哈希运算并基于直接输入的消息生成 $z$。

对于消息哈希，ECDSA\_DS 支持 SHA 算法 SHA-224（仅当选择 P-192 作为椭圆曲线时有效）和 SHA-256。

要使用 ECDSA\_DS SHA 接口，请完成以下步骤：

\begin{enumerate}
	\item 根据第 \ref{sec:ecdsa-msg-padding} 节中的描述，对消息进行填充。
	\item 将消息及其填充解析为消息块。详细信息请参见第 \ref{sec:ecdsa-msg-parsing} 节。
	\item \label{others:ecdsa-current-block} 处理当前消息块。
	      \begin{itemize}
		      \item 将当前消息块写入 \hyperref[tab:ecdsa-memory]{ECDSA\_DS\_MEM\_M}。
	      \end{itemize}
	\item 启动 ECDSA\_DS SHA 接口 \hyperref[others:ecdsa-note-sha]{$^1$}。
	      \begin{itemize}
		      \item 首次执行此步骤时，请将 1 写入 \hyperref[fielddesc:ECDSADSSHASTART]{ECDSA\_DS\_SHA\_START} 以启动 ECDSA\_DS SHA 接口；
		      \item 非首次执行此步骤 \hyperref[others:ecdsa-note-sha]{$^2$}，请将 1 写入 \hyperref[fielddesc:ECDSADSSHACONTINUE]{ECDSA\_DS\_SHA\_CONTINUE} 以继续运算。
	      \end{itemize}
	\item 查询当前消息块的处理进度。
	      \begin{itemize}
		      \item 轮询寄存器 \hyperref[fielddesc:ECDSADSSHABUSY]{ECDSA\_DS\_SHA\_BUSY}，直到其为 IDLE，表示接口已完成当前消息块的运算。
	      \end{itemize}

	\item 处理下一个消息块：
	      \begin{itemize}
		      \item 如有下一个消息块，则返回到步骤 \ref{others:ecdsa-current-block}。
		      \item 如没有更多的消息块，退出。
	      \end{itemize}

\end{enumerate}

\begin{tiplisting}\label{others:ecdsa-note-sha}
\vspace{-2.5em}
\begin{enumerate}
\item 在此步骤中，软件还可以在接口启动 SHA 运算时将下一个要处理的消息块（如有）写入寄存器 \hyperref[tab:ecdsa-memory]{ECDSA\_DS\_MEM\_M}，以节省时间。
\item 即正在继续之前暂停的 ECDSA\_DS SHA 接口运算。
\end{enumerate}
\end{tiplisting}

    \item clk\_apb\_ecdsa：用于配置 ECDSA\_DS 寄存器的总线时钟

ECDSA\_DS 支持一个复位域，向 \hyperref[fielddesc:HPSYSCLKRSTREGCRYPTOECDSARSTEN]{HP\_SYS\_CLKRST\_REG\_CRYPTO\_ECDSA\_RST\_EN} 先写 1 再写 0，即可复位整个 ECDSA\_DS 模块。

\section{中断}
\label{sec:ecdsa-interrupt}

\chipname{} 的 ECDSA\_DS 模块可以生成一个中断信号 ECDSA\_DS\_INTR 并发送给 \hyperref[mod:intmtrx]{中断矩阵}。

ECDSA\_DS 有四个中断源可产生中断信号 ECDSA\_DS\_INTR，如下所示。每个中断源都有一组通用的配置寄存器，详见章节 \hyperref[interrupt-config-registers]{\textit{中断配置寄存器}}。

\begin{itemize}
	\item \label{int:ECDSADSPREPDONEINT}ECDSA\_DS\_PREP\_DONE\_INT：在 PREP 阶段结束时触发。可以通过以下寄存器配置此中断源：
	      \begin{itemize}
		      \item \hyperref[fielddesc:ECDSADSPREPDONEINTRAW]{ECDSA\_DS\_PREP\_DONE\_INT\_RAW}：存储 ECDSA\_DS\_PREP\_DONE\_INT 的原始中断状态。
		      \item \hyperref[fielddesc:ECDSADSPREPDONEINTST]{ECDSA\_DS\_PREP\_DONE\_INT\_ST}：代表 ECDSA\_DS\_PREP\_DONE\_INT 中断的状态。通过 \hyperref[fielddesc:ECDSADSPREPDONEINTRAW]{ECDSA\_DS\_PREP\_DONE\_INT\_RAW} 字段启用/禁用此字段生成。
		      \item \hyperref[fielddesc:ECDSADSPREPDONEINTENA]{ECDSA\_DS\_PREP\_DONE\_INT\_ENA}：启用/禁用 ECDSA\_DS\_PREP\_DONE\_INT 中断。
		      \item \hyperref[fielddesc:ECDSADSPREPDONEINTCLR]{ECDSA\_DS\_PREP\_DONE\_INT\_CLR}：将此位设置为 1 以清除 ECDSA\_DS\_PREP\_DONE\_INT 中断状态。通过将此位设置为 1，字段 \hyperref[fielddesc:ECDSADSPREPDONEINTRAW]{ECDSA\_DS\_PREP\_DONE\_INT\_RAW} 和 \hyperref[fielddesc:ECDSADSPREPDONEINTST]{ECDSA\_DS\_PREP\_DONE\_INT\_ST} 将被清除。
	      \end{itemize}
          \item \label{int:ECDSADSPROCDONEINT}ECDSA\_DS\_PROC\_DONE\_INT：在 PROC 阶段结束时触发。可以通过以下寄存器配置此中断源：
	      \begin{itemize}
		      \item \hyperref[fielddesc:ECDSADSPROCDONEINTRAW]{ECDSA\_DS\_PROC\_DONE\_INT\_RAW}：存储 ECDSA\_DS\_PROC\_DONE\_INT 的原始中断状态。
		      \item \hyperref[fielddesc:ECDSADSPROCDONEINTST]{ECDSA\_DS\_PROC\_DONE\_INT\_ST}：代表 ECDSA\_DS\_PROC\_DONE\_INT 中断的状态。通过 \hyperref[fielddesc:ECDSADSPROCDONEINTRAW]{ECDSA\_DS\_PROC\_DONE\_INT\_RAW} 字段启用/禁用此字段生成。
		      \item \hyperref[fielddesc:ECDSADSPROCDONEINTENA]{ECDSA\_DS\_PROC\_DONE\_INT\_ENA}：启用/禁用 ECDSA\_DS\_PROC\_DONE\_INT 中断。
		      \item \hyperref[fielddesc:ECDSADSPROCDONEINTCLR]{ECDSA\_DS\_PROC\_DONE\_INT\_CLR}：将此位设置为 1 以清除 ECDSA\_DS\_PROC\_DONE\_INT 中断状态。通过将此位设置为 1，字段 \hyperref[fielddesc:ECDSADSPROCDONEINTRAW]{ECDSA\_DS\_PROC\_DONE\_INT\_RAW} 和 \hyperref[fielddesc:ECDSADSPROCDONEINTST]{ECDSA\_DS\_PROC\_DONE\_INT\_ST} 将被清除。
	      \end{itemize}
          \item \label{int:ECDSADSPOSTDONEINT}ECDSA\_DS\_POST\_DONE\_INT：在 POST 阶段结束时触发。可以通过以下寄存器配置此中断源：
	      \begin{itemize}
		      \item \hyperref[fielddesc:ECDSADSPOSTDONEINTRAW]{ECDSA\_DS\_POST\_DONE\_INT\_RAW}：存储 ECDSA\_DS\_POST\_DONE\_INT 的原始中断状态。
		      \item \hyperref[fielddesc:ECDSADSPOSTDONEINTST]{ECDSA\_DS\_POST\_DONE\_INT\_ST}：代表 ECDSA\_DS\_POST\_DONE\_INT 中断的状态。通过 \hyperref[fielddesc:ECDSADSPOSTDONEINTRAW]{ECDSA\_DS\_POST\_DONE\_INT\_RAW} 字段启用/禁用此字段生成。
		      \item \hyperref[fielddesc:ECDSADSPOSTDONEINTENA]{ECDSA\_DS\_POST\_DONE\_INT\_ENA}：启用/禁用 ECDSA\_DS\_POST\_DONE\_INT 中断。
		      \item \hyperref[fielddesc:ECDSADSPOSTDONEINTCLR]{ECDSA\_DS\_POST\_DONE\_INT\_CLR}：将此位设置为 1 以清除 ECDSA\_DS\_POST\_DONE\_INT 中断状态。通过将此位设置为 1，字段 \hyperref[fielddesc:ECDSADSPOSTDONEINTRAW]{ECDSA\_DS\_POST\_DONE\_INT\_RAW} 和 \hyperref[fielddesc:ECDSADSPOSTDONEINTST]{ECDSA\_DS\_POST\_DONE\_INT\_ST} 将被清除。
	      \end{itemize}
	\item \label{int:ECDSADSSHARELEASEINT}ECDSA\_DS\_SHA\_RELEASE\_INT：在 SHA 释放时触发。可以通过以下寄存器配置此中断源：
	      \begin{itemize}
		      \item \hyperref[fielddesc:ECDSADSSHARELEASEINTRAW]{ECDSA\_DS\_SHA\_RELEASE\_INT\_RAW}：存储 ECDSA\_DS\_SHA\_RELEASE\_INT 的原始中断状态。
		      \item \hyperref[fielddesc:ECDSADSSHARELEASEINTST]{ECDSA\_DS\_SHA\_RELEASE\_INT\_ST}：代表 ECDSA\_DS\_SHA\_RELEASE\_INT 中断的状态。通过 \hyperref[fielddesc:ECDSADSSHARELEASEINTRAW]{ECDSA\_DS\_SHA\_RELEASE\_INT\_RAW} 字段启用/禁用此字段生成。
		      \item \hyperref[fielddesc:ECDSADSSHARELEASEINTENA]{ECDSA\_DS\_SHA\_RELEASE\_INT\_ENA}：启用/禁用 ECDSA\_DS\_SHA\_RELEASE\_INT 中断。
		      \item \hyperref[fielddesc:ECDSADSSHARELEASEINTCLR]{ECDSA\_DS\_SHA\_RELEASE\_INT\_CLR}：将此位设置为 1 以清除 ECDSA\_DS\_SHA\_RELEASE\_INT 中断状态。通过将此位设置为 1，字段 \hyperref[fielddesc:ECDSADSSHARELEASEINTRAW]{ECDSA\_DS\_SHA\_RELEASE\_INT\_RAW} 和 \hyperref[fielddesc:ECDSADSSHARELEASEINTST]{ECDSA\_DS\_SHA\_RELEASE\_INT\_ST} 将被清除。
	      \end{itemize}
\end{itemize}

\begin{tiplisting}
中断、中断源、中断信号等术语的解释以及它们之间的联系请参考章节 \ref{mod:intmtrx} \textit{\nameref{mod:intmtrx}} > \ref{sec:intmtx-int-terminology} \textit{\nameref{sec:intmtx-int-terminology}}。

\section{寄存器列表}
\label{sec:ecdsa-reg-summ}

本小节的所有地址均为相对于 ECDSA\_DS 基地址的地址偏移量（相对地址），具体基地址请见章节 \ref{mod:sysmem} \textit{\nameref{mod:sysmem}} 中的表 \ref{tab:sysmem-base-address}。

为了提高安全性，在不同工作状态下，ECDSA\_DS 寄存器的读写权限不同。以下是每个工作状态的缩写及其与阶段的对应关系：

\begin{itemize}
    \item PI：IDLE 状态，对应 IDLE 阶段。
    \item PL：LOAD 状态，对应 LOAD 阶段。
    \item PG：GAIN 状态，对应 GAIN 阶段。
    \item PB：BUSY 状态，对应 PREP、PROC 和 POST 阶段。
\end{itemize}

请查看章节 \hyperref[glossary-access-types]{寄存器的访问类型}，了解“访问”列缩写的含义。
