\chapter{JPEG Codec}
\label{mod:jpegcodec}

\chipname{}'s JPEG codec complies with the JPEG baseline standard and supports both image compression (encoding) and decompression (decoding). By reducing the bandwidth required for image transmission and the storage space required for high-resolution images, the codec makes it practical to work with high-resolution images.

The encoding process consists of the following steps: discrete cosine transform (DCT), zigzag scanning, quantization, and Huffman coding.

The decoding process consists of the following steps: Huffman decoding, inverse quantization, inverse zigzag scanning, and inverse discrete cosine transform (IDCT).

\section{Terminology}
\label{sec:jpegcodec-term}
\begin{longtable}[c]{ R{4cm} p{12cm} }
\textbf{MCU} & Minimum coded unit. The basic unit of codec processing \\
\textbf{baseline} & A particular sequential DCT-based encoding and decoding process specified in the standard, which is required for all DCT-based decoding processes \\
\textbf{image} & A set of two-dimensional arrays of integer data \\
\textbf{component} & One of the two-dimensional arrays that comprise an image \\
\textbf{data unit} & An 8 × 8 block of pixels of one component \\
\textbf{marker} & A two-byte code in which the first byte is hexadecimal FF (0xFF) and the second byte is a value between 1 and hexadecimal FE (0xFE). It is served to identify the various structural parts of the compressed data formats \\
\textbf{restart marker} & Used to isolate coded data segments and for application-specific uses, such as decoder re-synchronization and error recovery \\
\textbf{restart interval} & The integer number of MCUs processed between two restart markers \\
\textbf{scan} & A single pass through the data for one or more of the components in an image \\
\end{longtable}

\section{Overview}
\label{sec:jpegcodec-overview}

\chipname{}'s JPEG codec is based on the JPEG baseline standard. The standard specifies that encoding is completed through one or more scans, and each scan can process one or more minimum coded units (MCUs). An MCU consists of a sequence of data units; the sequence depends on the sampling factors of each image component. MCUs of different image formats may contain different data unit sequences, as shown in Table \ref{tab:data_unit_of_mcu} \textit{\nameref{tab:data_unit_of_mcu}}.

\begin{ThreePartTable}

At any given time, the JPEG codec can be configured as either an encoder or a decoder, but not both simultaneously:
\begin{itemize}
    \item When used as an encoder, it receives the image to be compressed from 2D DMA and sends the encoded bitstream to 2D DMA.
    \item When used as a decoder, it receives the coded bitstream from 2D DMA and sends the decoded image to 2D DMA.
\end{itemize}

\section{Feature List}
\label{sec:jpegcodec-features}

When used as an encoder, the JPEG codec has the following features:
\begin{itemize}
    \item Pause during encoding
    \item Discrete cosine transform (DCT) algorithm
    \item Canonical Huffman coding
    \item Supported input image formats:
        \begin{itemize}
            \item YUV444, YUV422, YUV420, and GRAY
            \item RGB888 and RGB565 (after conversion to YUV444, YUV422, or YUV420)
        \end{itemize}
    \item Four configurable quantization coefficient tables with 8-bit or 12-bit precision
    \item Performance:
        \begin{itemize}
            \item Still image compression: up to 4K resolution
            \item Dynamic image compression: up to 720P@30 fps (excluding header encoding time)
        \end{itemize}
    \item Automatic zero-byte stuffing
    \item Automatic EOI marker insertion
    \item Timeout detection
\end{itemize}

When used as a decoder, the JPEG codec has the following features:
\begin{itemize}
    \item Inverse discrete cosine transform (IDCT) algorithm
    \item Huffman decoding
    \item Compressed bitstream decoding for YUV444, YUV422, YUV420, and GRAY image formats
    \item RST marker parsing
    \item Four configurable quantization coefficient tables with 8-bit or 12-bit precision
    \item Two DC and two AC Huffman tables
    \item Image decoding at any resolution. The output resolution is rounded up according to the input image format and may differ from the original resolution in the bitstream:
        \begin{itemize}
        \item YUV444, GRAY: both horizontal and vertical resolutions are rounded up to multiples of 8. For example, a 150 × 150 image has an output resolution of 152 × 152
        \item YUV422: horizontal resolution is rounded up to a multiple of 16, and vertical resolution to a multiple of 8. For example, a 150 × 150 image has an output resolution of 160 × 152
        \item YUV420: both horizontal and vertical resolutions are rounded up to multiples of 16. For example, a 150 × 150 image has an output resolution of 160 × 160
        \end{itemize}
    \item Timeout detection
    \item Performance:
    \begin{itemize}
        \item Still image decoding: up to 4K resolution
        \item Dynamic image decoding: up to 720P@30 fps (excluding header parsing time)
    \end{itemize}
\end{itemize}

\section{Architectural Overview}
\label{sec:jpegcodec-arch-overview}

When the JPEG codec is configured as an encoder, its architecture is shown in Figure \ref{fig:jpeg-enc-arc} \textit{\nameref{fig:jpeg-enc-arc}}.
\begin{figure}[H]
    \centering
    \includegraphics[width=1\textwidth]{\modulefiles/figures/jpeg-enc-arc}
    \caption{JPEG Encoder Architecture}
    \label{fig:jpeg-enc-arc}
\end{figure}

\begin{itemize}
    \item \textbf{rgb2ycrcb} implements color space conversion and converts the original image to a compressible image format supported by the codec
    \item \textbf{dct\_idct} performs two-dimensional DCT on data units
    \item \textbf{zigzag} performs zigzag scanning and sorting on DCT-transformed data units
    \item \textbf{quant\_table} stores the quantization coefficient table delivered by the software
    \item \textbf{quantizer} quantizes zigzag-sorted data based on the quantization coefficient table stored in \textbf{quant\_table}
    \item \textbf{huffman\_encoder} performs Huffman encoding on quantized data units
    \item \textbf{packer} packs Huffman-encoded data in groups of 32 bits and outputs the encoded bitstream
\end{itemize}

When the JPEG codec is configured as a decoder, its architecture is shown in Figure \ref{fig:jpeg-dec-arc} \textit{\nameref{fig:jpeg-dec-arc}}.
\begin{figure}[H]
    \centering
    \includegraphics[width=1.0\textwidth]{\modulefiles/figures/jpeg-dec-arc}
    \caption{JPEG Decoder Architecture}
    \label{fig:jpeg-dec-arc}
\end{figure}

\begin{itemize}
    \item \textbf{header\_dec} extracts the bitstream, parses SOS and EOI markers, and controls the decoding process
    \item \textbf{huffman\_decoder} stores the Huffman table delivered by the software, and performs Huffman decoding on the bitstream
    \item \textbf{quant\_table} stores the quantization coefficient table delivered by the software
    \item \textbf{dequantizer} dequantizes Huffman-decoded data based on the quantization coefficient table stored in \textbf{quant\_table}
    \item \textbf{dezigzag} performs inverse zigzag scanning and sorting on dequantized data, and restores data units
    \item \textbf{dct\_idct} performs two-dimensional inverse DCT on dezigzag-sorted data units, and outputs decoded data units
\end{itemize}

Since the JPEG codec cannot be used as an encoder and decoder at the same time, the encoder and decoder share the \textbf{quant\_table} and \textbf{dct\_idct} modules to save hardware resources.

\section{Functional Description}
\label{sec:jpegcodec-func-descr}

The JPEG codec operates as either an encoder or a decoder.

\subsection{JPEG Encoder}
\label{sec:jpegcodec-enc-mode}

\subsubsection{Pause}
\label{sec:jpegcodec-enc-pause}

The JPEG encoder can be paused when higher-priority tasks are executed. This feature is controlled by the \hyperref[fielddesc:JPEGPAUSEEN]{JPEG\_PAUSE\_EN} bit.

\begin{itemize}
    \item When \hyperref[fielddesc:JPEGPAUSEEN]{JPEG\_PAUSE\_EN} is set to 1, the JPEG encoder stops outputting the bitstream to the 2D DMA RX channel.
    \item When \hyperref[fielddesc:JPEGPAUSEEN]{JPEG\_PAUSE\_EN} is cleared to 0, the JPEG encoder resumes and outputs the bitstream normally.
\end{itemize}

\subsubsection{Color Space Conversion}
\label{sec:jpegcodec-enc-csc}

According to the JPEG standard, the image formats supported by the JPEG encoder are YUV444, YUV422, YUV420, and GRAY. With integrated color space conversion, \chipname{}'s JPEG encoder converts RGB888 and RGB565 formats to these encoder-supported formats before encoding, so it supports a wider set of input formats.

The color space conversion formulas for converting RGB to YUV are:
\begin{center}
$Y = (0.299 \times R) + (0.587 \times G) + (0.114 \times B)$ \\
$U = (-0.1687 \times R) + (-0.3313 \times G) + (0.5 \times B) + 128$ \\
$V = (0.5 \times R) + (-0.4187 \times G) + (-0.0813 \times B) + 128$ \\
\end{center}

\subsubsection{Configurable Quantization Coefficient Table}
\label{sec:jpegcodec-enc-qnr}

\chipname{}'s JPEG encoder hardware supports four 8 × 8 quantization coefficient tables, each of which can be configured with 64 coefficient values via software.

The precision of each quantization table is configured via \hyperref[fielddesc:JPEGQNRPRECISION]{JPEG\_QNR\_PRECISION}:
\begin{itemize}
    \item 0: lower 8 bits are valid
    \item 1: lower 12 bits are valid
\end{itemize}

The configuration mode for quantization table coefficients is selected via \hyperref[fielddesc:JPEGQNRFIFOEN]{JPEG\_QNR\_FIFO\_EN}:
\begin{itemize}
    \item 0: non-FIFO mode; each coefficient is written to a specific address
    \item 1: FIFO mode; all coefficients are written to the same address
\end{itemize}

The configuration method differs between modes. Note that \regindex{n} (\regindex{n} = 0, 1, 2, 3) is the index of each quantization coefficient table.
\begin{itemize}
    \item Non-FIFO mode: all quantization coefficients in quantization coefficient table \regindex{n} must be written by position to a specific address, i.e., (JPEG codec base address + \regindex{n} * 0x100 + \regindex{quantization coefficient position number} * 0x4), where \regindex{quantization coefficient position number} can be 0, 1, 2, ..., 63 (see Table \ref{tab:example_qnr} \textit{\nameref{tab:example_qnr}}). In this mode, since each coefficient is written to a specific address, the 64 quantization coefficients do not need to be configured in sequence.
    \item FIFO mode: all 64 quantization coefficients in quantization coefficient table \regindex{n} are written to the same address, i.e., \hyperref[regdesc:JPEGT0QNRREG]{JPEG\_T\regindex{n}QNR\_REG}. In this mode, since all coefficients are written to the same address, the 64 quantization coefficients must be configured in sequence. The hardware then automatically stores the 64 quantization coefficients in the order shown in Table \ref{tab:example_qnr} \textit{\nameref{tab:example_qnr}}.
\end{itemize}

If fewer than four quantization tables are used, the unused tables do not need to be configured.

To use quantization coefficient table \regindex{n} for the luminance or chrominance component, set the corresponding register field to \regindex{n}:
\begin{itemize}
    \item Luminance component: \hyperref[fielddesc:JPEGLQNRTBLSEL]{JPEG\_LQNR\_TBL\_SEL}
    \item Chrominance component: \hyperref[fielddesc:JPEGCQNRTBLSEL]{JPEG\_CQNR\_TBL\_SEL}
\end{itemize}

\subsubsection{Stuffed Zero Byte}
\label{sec:jpegcodec-enc-zero_byte}

The JPEG baseline standard requires that no marker appear within a Huffman-coded segment. Each 0xFF byte generated by Huffman coding must be followed by a stuffed 0x00 byte.

The JPEG encoder implements this feature and can automatically stuff a 0x00 byte after each 0xFF byte in the Huffman-coded segment of the bitstream.

Whether to add a 0x00 byte after each 0xFF byte is configured via \hyperref[fielddesc:JPEGFFCHECKEN]{JPEG\_FF\_CHECK\_EN}:
\begin{itemize}
    \item 0: do not add
    \item 1: add (default)
\end{itemize}

\subsubsection{EOI Marker}
\label{sec:jpegcodec-enc-eoi}

The end-of-image (EOI) marker marks the end of a compressed image bitstream. The EOI marker code is 0xFFD9.

The JPEG encoder can automatically add the EOI marker at the end of the bitstream.

Whether to add the EOI marker is configured via \hyperref[fielddesc:JPEGTAILEREN]{JPEG\_TAILER\_EN}:
\begin{itemize}
    \item 0: do not add
    \item 1: add
\end{itemize}

\subsubsection{Timeout Detection}
\label{sec:jpegcodec-enc-timeout}

The JPEG codec supports timeout detection when used as an encoder. The hardware triggers the timeout interrupt JPEG\_ENCODE\_TIMEOUT\_INT when:
\begin{itemize}
    \item the encoder cannot write the encoded bitstream to 2D DMA for more than ($ 2 ^ {\hyperref[fielddesc:JPEGENCODETIMEOUTTHRES]{JPEG\_ENCODE\_TIMEOUT\_THRES}} - 1 $) clock cycles
\end{itemize}

\subsection{JPEG Decoder}
\label{sec:jpegcodec-dec-mode}

The information in the bitstream must first be parsed by software, and then sent to the hardware through the APB configuration bus. Note that the hardware does not support parsing any marker segments other than SOS, RST, and EOI marker segments.

\subsubsection{Multiple Components}
\label{sec:jpegcodec-dec-color_components}


The frame header contains the number of components, the ID of each component, and the horizontal and vertical sampling factors of each component.

The JPEG decoder software must parse this information and write it to the corresponding registers \hyperref[fielddesc:JPEGCOMPONENTNUM]{JPEG\_COMPONENT\_NUM}, \hyperref[regdesc:JPEGC0REG]{JPEG\_C\regindex{n}\_ID}, \hyperref[fielddesc:JPEGC0XFACTOR]{JPEG\_C\regindex{n}\_X\_FACTOR}, and \hyperref[fielddesc:JPEGC0YFACTOR]{JPEG\_C\regindex{n}\_Y\_FACTOR}. Here, \regindex{n} can be 0, 1, or 2, indicating that the hardware supports up to three components (for example, Y, U, and V in YUV). If fewer than three components are used, the registers corresponding to the unused components do not need to be configured.

The hardware checks whether the value of each component register \hyperref[regdesc:JPEGC0REG]{JPEG\_C\regindex{n}\_ID} matches the ID in the scan header information. The sampling factor indicates the number of data units of that component contained in one MCU in the horizontal and vertical directions. Regardless of the format of the image to be decoded, the decoder supports only one scan that contains all components. After decoding, the image is sent to 2D DMA. For the layout of each decoded image format, see Chapter \ref{mod:2ddma} \textit{\nameref{mod:2ddma}}.

\subsubsection{Parsing RST Marker}
\label{sec:jpegcodec-dec-rst_marker}

The bitstream may have a restart (RST) marker in the scan segment. The RST marker code is 0xFFD\regindex{x} (\regindex{x} = 0, 1, ..., 7).

The JPEG decoder hardware can parse RST markers and check whether the actual number of MCUs between two RST markers matches the restart interval defined in the DRI segment of the Tables/Miscellaneous segment.

First, software parses the DRI segment and writes the restart interval to \hyperref[fielddesc:JPEGRESTARTINTERVAL]{JPEG\_RESTART\_INTERVAL}. Then, after every \hyperref[fielddesc:JPEGRESTARTINTERVAL]{JPEG\_RESTART\_INTERVAL} MCUs are decoded, the hardware checks whether the subsequent bitstream contains an RST marker.

If \hyperref[fielddesc:JPEGRESTARTINTERVAL]{JPEG\_RESTART\_INTERVAL} is 0, the bitstream contains no RST markers and the hardware does not check for them.

\subsubsection{Configurable Quantization Coefficient Table}
\label{sec:jpegcodec-dec-qnr}

\chipname{}'s JPEG decoder also supports four configurable quantization coefficient tables. Since the JPEG codec cannot be used as an encoder and decoder at the same time, the decoder can share the same four configurable coefficient tables with the encoder to save hardware resources.

The decoder quantization coefficient table configuration is similar to that of the encoder (see Section \ref{sec:jpegcodec-enc-qnr} \textit{\nameref{sec:jpegcodec-enc-qnr}}), with the following differences:
\begin{itemize}
    \item The software needs to parse the DQT segment in the Tables/Miscellaneous segment to obtain the quantization coefficient tables of the decoder. The recommended quantization coefficient tables are the same as the encoder shown in Table \ref{tab:luminance_qnr} \textit{\nameref{tab:luminance_qnr}} and Table \ref{tab:chrominance_qnr} \textit{\nameref{tab:chrominance_qnr}}.
    \item The precision of quantization coefficient table \regindex{n} is configured via bit[4] of \hyperref[regdesc:JPEGDQTINFOREG]{JPEG\_T\regindex{n}\_DQT\_INFO}:
    \begin{itemize}
        \item 0: lower 8 bits are valid
        \item 1: higher 12 bits are valid
    \end{itemize}
    The precision is also obtained from the DQT segment in the Tables/Miscellaneous segment.
    \item Each component can select a different quantization coefficient table. The lower 4 bits of \hyperref[regdesc:JPEGDQTINFOREG]{JPEG\_T\regindex{n}\_DQT\_INFO} configure the quantization coefficient table ID, and \hyperref[fielddesc:JPEGC0DQTTBLSEL]{JPEG\_C\regindex{n}\_DQT\_TBL\_SEL} configures the quantization coefficient table selected for each component. The ID of each quantization coefficient table is also obtained from the DQT segment in the Tables/Miscellaneous segment.
\end{itemize}

\subsubsection{Configurable Huffman Table}
\label{sec:jpegcodec-dec-huffman}

\chipname{} supports up to two DC Huffman tables and two AC Huffman tables, which can be configured as needed within the hardware limits.

Each Huffman table contains three types of information, which can be obtained from the DHT segment in the Tables/Miscellaneous segment:
\begin{itemize}
    \item the number of codewords with lengths from 1 to 16 bits
    \item the symbols corresponding to decoded codewords
    \begin{itemize}
        \item DC table: up to 16 symbols
        \item AC table: up to 256 symbols
    \end{itemize}
    \item the minimum codewords with lengths from 1 to 16 bits
\end{itemize}

DC and AC Huffman tables are configured in FIFO or non-FIFO mode via \hyperref[fielddesc:JPEGDHTFIFOEN]{JPEG\_DHT\_FIFO\_EN}:
\begin{itemize}
    \item 0: non-FIFO mode
    \item 1: FIFO mode
\end{itemize}

In different modes, the Huffman table configuration differs. The following describes DC table \regindex{n} (\regindex{n} = 0, 1):
\begin{itemize}
    \item Non-FIFO mode: write each type of information for DC\regindex{n} to its type-specific address.
    \begin{itemize}
        \item Number of codewords with lengths from 1 to 16 bits: JPEG codec base address + 0x500 + \regindex{n} * 0x80 + (\regindex{codeword length} - 1) * 0x4, where \regindex{codeword length} = 1, 2, ..., 16.
        \item Symbols corresponding to decoded codewords: JPEG codec base address + 0x600 + \regindex{n} * 0x40 + \regindex{symbol number} * 0x4, where \regindex{symbol number} = 0, 1, ..., 15.
        \item Minimum codewords with lengths from 1 to 16 bits: JPEG codec base address + 0xF00 + \regindex{n} * 0x80 + (\regindex{codeword length} - 1) * 0x4, where \regindex{codeword length} = 1, 2, ..., 16.
    \end{itemize}
    In this mode, information of each type does not need to be written in sequence.
    \item FIFO mode: write all information of the same type for DC\regindex{n} to the same address.
    \begin{itemize}
        \item Number of codewords with lengths from 1 to 16 bits: \hyperref[regdesc:JPEGDHTTOTLENDC0REG]{JPEG\_DHT\_TOTLEN\_DC\regindex{n}\_REG}.
        \item All symbols corresponding to decoded codewords (DC table: up to 16 symbols): \hyperref[regdesc:JPEGDHTVALDC0REG]{JPEG\_DHT\_VAL\_DC\regindex{n}\_REG}.
        \item Minimum codewords with lengths from 1 to 16 bits: \hyperref[regdesc:JPEGDHTCODEMINDC0REG]{JPEG\_DHT\_CODEMIN\_DC\regindex{n}\_REG}.
    \end{itemize}
    In this mode, information of each type must be written in sequence. The hardware then stores it in order.
\end{itemize}

The AC\regindex{n} (\regindex{n} = 0, 1) table configuration is similar to that of DC\regindex{n} (\regindex{n} = 0, 1):

\begin{itemize}
    \item Non-FIFO mode: write each type of information for AC\regindex{n} to its type-specific address.
    \begin{itemize}
        \item Number of codewords with lengths from 1 to 16 bits: JPEG codec base address + 0x540 + \regindex{n} * 0x80 + (\regindex{codeword length} - 1) * 0x4, where \regindex{codeword length} = 1, 2, ..., 16.
        \item Symbols corresponding to decoded codewords: JPEG codec base address + 0x680 + \regindex{n} * 0x400 + \regindex{symbol number} * 0x4, where \regindex{symbol number} = 0, 1, ..., 255.
        \item Minimum codewords with lengths from 1 to 16 bits: JPEG codec base address + 0xF40 + \regindex{n} * 0x80 + (\regindex{codeword length} - 1) * 0x4, where \regindex{codeword length} = 1, 2, ..., 16.
    \end{itemize}
    In this mode, information of each type does not need to be written in sequence.
    \item FIFO mode: write all information of the same type for AC\regindex{n} to the same address.
    \begin{itemize}
        \item Number of codewords with lengths from 1 to 16 bits: \hyperref[regdesc:JPEGDHTTOTLENAC0REG]{JPEG\_DHT\_TOTLEN\_AC\regindex{n}\_REG}.
        \item All symbols corresponding to decoded codewords (AC table: up to 256 symbols): \hyperref[regdesc:JPEGDHTVALAC0REG]{JPEG\_DHT\_VAL\_AC\regindex{n}\_REG}.
        \item Minimum codewords with lengths from 1 to 16 bits: \hyperref[regdesc:JPEGDHTCODEMINAC0REG]{JPEG\_DHT\_CODEMIN\_AC\regindex{n}\_REG}.
    \end{itemize}
    In this mode, information of each type must be written in sequence. The hardware then stores it in order.
\end{itemize}

Minimum codewords with lengths from 1 to 16 bits must be left-aligned in the 16-bit configuration value. If no codeword exists for a given length, set the configuration value to 0xFFFF. For example, if the minimum codeword is 0x7C, the 16-bit configuration value is 0x7C00.

Recommended DC and AC Huffman tables for the JPEG baseline standard are in \href{https://www.itu.int/rec/T-REC-T.81}{ITU T.81 Recommendation}.

The software obtains the IDs of the DC\regindex{n} and AC\regindex{n} Huffman tables by parsing the DHT segment in the Tables/Miscellaneous segment, and writes the IDs to the corresponding fields \hyperref[regdesc:JPEGDHTINFOREG]{JPEG\_DC\regindex{n}\_DHT\_ID} and \hyperref[regdesc:JPEGDHTINFOREG]{JPEG\_AC\regindex{n}\_DHT\_ID}.

The hardware automatically uses the DC\regindex{n} and AC\regindex{n} Huffman tables whose IDs match \hyperref[regdesc:JPEGDHTINFOREG]{JPEG\_DC\regindex{n}\_DHT\_ID} and \hyperref[regdesc:JPEGDHTINFOREG]{JPEG\_AC\regindex{n}\_DHT\_ID}.

\subsubsection{Timeout Detection}
\label{sec:jpegcodec-dec-timeout}

The JPEG codec supports timeout detection when used as a decoder. The hardware triggers the timeout interrupt JPEG\_DECODE\_TIMEOUT\_INT when:
\begin{itemize}
    \item the decoder stops reading the bitstream for more than ($ 2 ^ {\hyperref[fielddesc:JPEGDECODETIMEOUTTHRES]{JPEG\_DECODE\_TIMEOUT\_THRES}} - 1 $) clock cycles
\end{itemize}

After the timeout interrupt is triggered, the decoder is reset according to the configuration of \hyperref[fielddesc:JPEGDECODETIMEOUTTASKSEL]{JPEG\_DECODE\_TIMEOUT\_TASK\_SEL}:
\begin{itemize}
    \item 0: the hardware takes no action; software must set \hyperref[fielddesc:JPEGSOFTRST]{JPEG\_SOFT\_RST} or \hyperref[fielddesc:JPEGFSMRST]{JPEG\_FSM\_RST} to perform a reset.
    \item 1: the hardware automatically resets the decoder, exits the timeout state, and returns to the initial state.
\end{itemize}

\section{Interrupts}
\label{sec:jpegcodec-interrupts}

\chipname{}'s JPEG Codec can generate the JPEG\_INTR interrupt signal that will be sent to the \href{mod:intmtrx}{Interrupt Matrix}.

Interrupt signal JPEG\_INTR can be generated by the following internal interrupt sources:
\begin{itemize}
\item JPEG\_DONE\_INT: Triggered when a frame of image encoding or decoding ends.
\item JPEG\_RLE\_PARALLEL\_ERR\_INT: Triggered when a run-length encoding error occurs.
\item JPEG\_CID\_ERR\_INT: Triggered when the decoded component ID is different from the component ID configured by the software.
\item JPEG\_C\_DHT\_DC\_ID\_ERR\_INT: Triggered when the decoded DC Huffman table ID of each component is not the software configured DC0 Huffman table ID or DC1 Huffman table ID.
\item JPEG\_C\_DHT\_AC\_ID\_ERR\_INT: Triggered when the decoded AC Huffman table ID of each component is not the software configured AC0 Huffman table ID or AC1 Huffman table ID.
\item JPEG\_C\_DQT\_ID\_ERR\_INT: Triggered when the decoded quantization table ID of each component is different from the software configured quantization table ID.
\item JPEG\_RST\_UXP\_ERR\_INT: Triggered when the \hyperref[fielddesc:JPEGRESTARTINTERVAL]{JPEG\_RESTART\_INTERVAL} configured by the software is 0 but the RST marker is parsed by the decoder.
\item JPEG\_RST\_CHECK\_NONE\_ERR\_INT: Triggered when the \hyperref[fielddesc:JPEGRESTARTINTERVAL]{JPEG\_RESTART\_INTERVAL} configured by the software is non-0 but the RST marker cannot be parsed by the decoder.
\item JPEG\_RST\_CHECK\_POS\_ERR\_INT: Triggered when the MCU number between two parsed RST markers is not equal to the \hyperref[fielddesc:JPEGRESTARTINTERVAL]{JPEG\_RESTART\_INTERVAL} configured by the software.
\item JPEG\_OUT\_EOF\_INT: Triggered when the EOF marker is read from the TX channel of 2D DMA.
\item JPEG\_SR\_COLOR\_MODE\_ERR\_INT: This interrupt is invalid.
\item JPEG\_DCT\_DONE\_INT: Triggered when the DCT or IDCT calculation of one data unit is completed.
\item JPEG\_BS\_LAST\_BLOCK\_EOF\_INT: Triggered when the encoding of the last data unit is completed.
\item JPEG\_SCAN\_CHECK\_NONE\_ERR\_INT: Triggered when an image frame has multiple scans to be decoded and the SOS marker is not parsed within (\hyperref[fielddesc:JPEGSOSCHECKBYTENUM]{JPEG\_SOS\_CHECK\_BYTE\_NUM} + 1) bytes in any scan header information.
\item JPEG\_SCAN\_CHECK\_POS\_ERR\_INT: Triggered when the position of the scan header information parsed by the decoder is wrong.
\item JPEG\_UXP\_DET\_INT: Triggered when the marker parsed by the decoder is not supported by the hardware.
\item JPEG\_EN\_FRAME\_EOF\_ERR\_INT: Triggered when the number of data units to be encoded read from 2D DMA is less than the number of data units calculated based on the image resolution configured by the software.
\item JPEG\_EN\_FRAME\_EOF\_LACK\_INT: Triggered when a frame of image to be encoded is completely read from 2D DMA but the EOF marker is not read.
\item JPEG\_DE\_FRAME\_EOF\_ERR\_INT: Triggered when the number of data units obtained after decoding a frame of image is different from the number of data units calculated based on the image resolution configured by the software.
\item JPEG\_DE\_FRAME\_EOF\_LACK\_INT: Triggered when the bitstream of an image is completely read from 2D DMA but neither the EOF marker nor the EOI marker is read.
\item JPEG\_SOS\_UNMATCH\_ERR\_INT: Triggered when either of the following occurs in the scan header information parsed by the decoder:
\begin{itemize}
    \item The number of components is 0
    \item The header length does not match the actual header length
\end{itemize}
\item JPEG\_MARKER\_ERR\_FST\_SCAN\_INT: Triggered when there is an error in the first scan header information parsed by the decoder. The errors include those that trigger:
\begin{itemize}
    \item JPEG\_CID\_ERR\_INT
    \item JPEG\_C\_DHT\_DC\_ID\_ERR\_INT
    \item JPEG\_C\_DHT\_AC\_ID\_ERR\_INT
    \item JPEG\_C\_DQT\_ID\_ERR\_INT
    \item JPEG\_SOS\_UNMATCH\_ERR\_INT
\end{itemize}
\item JPEG\_MARKER\_ERR\_OTHER\_SCAN\_INT: Triggered when there is an error in a non-first scan header information parsed by the decoder. The error types are the same as those that trigger JPEG\_MARKER\_ERR\_FST\_SCAN\_INT.
\item JPEG\_UNDET\_INT: Triggered when the bitstream of an image is completely read from 2D DMA but the SOS marker is not read.
\item JPEG\_DECODE\_TIMEOUT\_INT: Triggered when the decoder times out.
\item JPEG\_ENCODE\_TIMEOUT\_INT: Triggered when the encoder times out.
\end{itemize}

The above interrupt sources can only be triggered when the interrupt enable register \regindex{interrupt\_source\_name}\_ENA is set to 1. Write 1 to \regindex{interrupt\_source\_name}\_CLR will clear the interrupt.

\begin{tiplisting}
For definitions of \textit{interrupt}, \textit{interrupt signal}, \textit{interrupt source}, and their correlations, please refer to Chapter \ref{mod:intmtrx} \textit{\nameref{mod:intmtrx}} > Section \ref{sec:intmtx-int-terminology} \textit{\nameref{sec:intmtx-int-terminology}}.
\end{tiplisting}

Each interrupt source can be configured by a common set of registers that are described in Section \hyperref[interrupt-config-registers]{\textit{Interrupt Configuration Registers}}. The specific registers can be found in Section \ref{sec:jpegcodec-reg-summ} \textit{\nameref{sec:jpegcodec-reg-summ}}.

\subsection{JPEG Encoder}
\label{sec:jpegcodec-enc-prog}

When the JPEG codec is working as an encoder, the configuration process is:
\begin{enumerate}
    \item Activate the JPEG codec:
    \begin{itemize}
        \item Set \hyperref[fielddesc:HPSYSCLKRSTJPEGSYSCLKEN]{HP\_SYS\_CLKRST\_JPEG\_SYS\_CLK\_EN} to 1 to enable the JPEG codec clock.
        \item Set \hyperref[fielddesc:HPSYSCLKRSTRSTENJPEG]{HP\_SYS\_CLKRST\_RST\_EN\_JPEG} to 0 to release the JPEG codec system-level reset.
    \end{itemize}
    \item Configure the JPEG codec:
    \begin{itemize}
        \item Set \hyperref[fielddesc:JPEGSOFTRST]{JPEG\_SOFT\_RST} to 1 to reset the JPEG codec, and then set \hyperref[fielddesc:JPEGSOFTRST]{JPEG\_SOFT\_RST} to 0 to release the JPEG codec reset.
        \item Set \hyperref[fielddesc:JPEGMODE]{JPEG\_MODE} to 0 to configure the JPEG codec to be used as an encoder.
        \item Configure the following fields to select the original image format:
        \begin{itemize}
            \item Format: \hyperref[fielddesc:JPEGCOLORSPACE]{JPEG\_COLOR\_SPACE}
            \item Pixel order: \hyperref[fielddesc:JPEGPIXELREV]{JPEG\_PIXEL\_REV}
        \end{itemize}
        See Table \ref{tab:csc_result} \textit{\nameref{tab:csc_result}}.
        \item Configure \hyperref[fielddesc:JPEGTAILEREN]{JPEG\_TAILER\_EN} to select whether to add the EOI marker (0xFFD9) at the end of the bitstream:
        \begin{itemize}
            \item 0: disable
            \item 1: enable
        \end{itemize}
        \item Configure \hyperref[fielddesc:JPEGSAMPLESEL]{JPEG\_SAMPLE\_SEL} to select the image format to be compressed:
                \begin{itemize}
                    \item 0: YUV444
                    \item 1: YUV422
                    \item 2: YUV420
                \end{itemize}
        Note that this field is valid only when the original image format is RGB. See Table \ref{tab:csc_result} \textit{\nameref{tab:csc_result}}.
        \item Configure \hyperref[fielddesc:JPEGHA]{JPEG\_HA} as the original image width and \hyperref[fielddesc:JPEGVA]{JPEG\_VA} as the original image height.
        \item Configure the quantization coefficient table by following the instructions in Section \ref{sec:jpegcodec-enc-qnr} \textit{\nameref{sec:jpegcodec-enc-qnr}}.
        \item Configure timeout detection by following the instructions in Section \ref{sec:jpegcodec-enc-timeout} \textit{\nameref{sec:jpegcodec-enc-timeout}}.
    \end{itemize}
    \item Configure 2D DMA (for configuration details and related concepts, see Chapter \ref{mod:2ddma} \textit{\nameref{mod:2ddma}}.)
    \begin{enumerate}
        \item Configure the linked list of 2D DMA TX channel.
        \begin{itemize}
            \item Set 2DEN to 1 to enable 2D function.
            \item Configure the Buffer address pointer as the starting address where the original image is stored.
            \item Configure pbyte to select the number of bytes of one pixel of the original image.
            \item Configure HA as the width of the original image and VA as the height of the original image.
            \item Configure hb as the number of pixels in the horizontal direction of an image block and vb as the number of pixels in the vertical direction of an image block.
            \item Configure mod as 1, which means continuous reading of image blocks of hb × vb size.
            \item Configure (X, Y) as the coordinate of the first pixel in the starting image block. According to the original image format and the image format to be compressed, hb and vb must meet the restrictions in Table \ref{tab:en_hb_vb} \textit{\nameref{tab:en_hb_vb}}:

        \\ \hline
        \rowcolor{lightgray}
        \textbf{Format of Original Image} & \textbf{Format of the Image to be Compressed}  &  \textbf{hb}  &  \textbf{vb}\\ \hline
        RGB  &  YUV444 &  Multiples of 8 &  Multiples of 8  \\ \hline

        \item Configure the linked list of the 2D DMA RX channel:

            \item Set 2DEN to 0 to enable 1D function.
            \item Configure the Buffer address pointer as the starting address where the encoded bitstream will be stored.
            \item Configure size as the number of bytes in the space to store the encoded bitstream.
            \item Configure mod as 0. mod is invalid when 2DEN is 0.

            \item Configure \hyperref[fielddesc:DMA2DINPERISELCHN]{DMA2D\_IN\_PERI\_SEL\_CH\regindex{n}} to 0 to connect the RX channel\regindex{n} to the JPEG codec.
        \end{itemize}
        \item Reset 2D DMA channels:
        \begin{itemize}
            \item 2D DMA TX channel\regindex{n}: Set \hyperref[fielddesc:DMA2DOUTRSTCHN]{DMA2D\_OUT\_RST\_CH\regindex{n}} to 1 to reset 2D DMA TX channel\regindex{n}, then set \hyperref[fielddesc:DMA2DOUTRSTCHN]{DMA2D\_OUT\_RST\_CH\regindex{n}} to 0 to release the reset of 2D DMA TX channel\regindex{n}.

        \begin{itemize}
            \item Configure \hyperref[fielddesc:DMA2DOUTMEMBURSTLENGTHCHN]{DMA2D\_OUT\_MEM\_BURST\_LENGTH\_CH\regindex{n}} to select the burst length of 2D DMA TX channel\regindex{n}.
            \item Configure \hyperref[fielddesc:DMA2DINMEMBURSTLENGTHCHN]{DMA2D\_IN\_MEM\_BURST\_LENGTH\_CH\regindex{n}} to select the burst length of 2D DMA RX channel\regindex{n}.
        \end{itemize}

See details in Table \ref{tab:en_block_size} \textit{\nameref{tab:en_block_size}}:
        \begin{itemize}
            \item 0: 8 × 8
            \item 1: 16 × 8
            \item 2: 16 × 16
        \end{itemize}

        \item Configure 2D DMA channel linked list address:
        \begin{itemize}
            \item 2D DMA TX channel: \hyperref[fielddesc:DMA2DOUTLINKADDRCHN]{DMA2D\_OUTLINK\_ADDR\_CH\regindex{n}}
            \item 2D DMA RX channel: \hyperref[fielddesc:DMA2DINLINKADDRCHN]{DMA2D\_INLINK\_ADDR\_CH\regindex{n}}

    \item Enable interrupt sources:
    \begin{itemize}
        \item \hyperref[regdesc:DMA2DOUTINTENACHNREG]{DMA2D\_OUT\_INT\_ENA\_CH\regindex{n}\_REG}
        \item \hyperref[regdesc:DMA2DININTENACHNREG]{DMA2D\_IN\_INT\_ENA\_CH\regindex{n}\_REG}
        \item \hyperref[regdesc:JPEGINTENAREG]{JPEG\_INT\_ENA\_REG}
    \end{itemize}
    \item Start the transmission of 2D DMA channels:

    \item Wait until DMA2D\_IN\_SUC\_EOF\_CH\regindex{n}\_INT becomes 1, indicating that the encoded bitstream has been completely written to memory.
\end{enumerate}


\subsection{JPEG Decoder}
\label{sec:jpegcodec-dec-prog}

When the JPEG codec is working as a decoder, the configuration process is:
\begin{enumerate}
    \item Activate the JPEG codec:
    \begin{itemize}
        \item Set \hyperref[fielddesc:HPSYSCLKRSTJPEGSYSCLKEN]{HP\_SYS\_CLKRST\_JPEG\_SYS\_CLK\_EN} to 1 to enable the JPEG codec clock.
        \item Set \hyperref[fielddesc:HPSYSCLKRSTRSTENJPEG]{HP\_SYS\_CLKRST\_RST\_EN\_JPEG} to 0 to release the JPEG codec system-level reset.
    \end{itemize}
    \item Configure the JPEG codec:
    \begin{itemize}
        \item Set \hyperref[fielddesc:JPEGSOFTRST]{JPEG\_SOFT\_RST} to 1 to reset the JPEG codec, and then set \hyperref[fielddesc:JPEGSOFTRST]{JPEG\_SOFT\_RST} to 0 to release the JPEG codec reset.
        \item Set \hyperref[fielddesc:JPEGMODE]{JPEG\_MODE} to 1 to configure the JPEG codec to be used as a decoder.
        \item Enable the RST marker check following the instructions in Section \ref{sec:jpegcodec-dec-rst_marker} \textit{\nameref{sec:jpegcodec-dec-rst_marker}}, if required.
        \item Configure the quantization coefficient tables by following the instructions in Section \ref{sec:jpegcodec-dec-qnr} \textit{\nameref{sec:jpegcodec-dec-qnr}}.
        \item Configure the Huffman tables by following the instructions in Section \ref{sec:jpegcodec-dec-huffman} \textit{\nameref{sec:jpegcodec-dec-huffman}}.
        \item Configure timeout detection by following the instructions in Section \ref{sec:jpegcodec-dec-timeout} \textit{\nameref{sec:jpegcodec-dec-timeout}}.
        \item Configure the width and height of the decoded image:
        \begin{itemize}
            \item Width: write the decoded image width to \hyperref[fielddesc:JPEGHA]{JPEG\_HA}.
            \item Height: write the height of the decoded image to \hyperref[fielddesc:JPEGVA]{JPEG\_VA}.
            \item According to different decoded image formats, \hyperref[fielddesc:JPEGHA]{JPEG\_HA} and \hyperref[fielddesc:JPEGVA]{JPEG\_VA} must meet the requirements of Table \ref{tab:de_jpeg_ha_va} \textit{\nameref{tab:de_jpeg_ha_va}}.
            \begin{longtable}{ | L{4cm} | L{4cm} | l | l |}
                \caption{JPEG Decoder \hyperref[fielddesc:JPEGHA]{JPEG\_HA} and \hyperref[fielddesc:JPEGVA]{JPEG\_VA} Configuration} \label{tab:de_jpeg_ha_va}
                \\ \hline
                \rowcolor{lightgray}
                \textbf{Format of Decoded Image} & \textbf{\hyperref[fielddesc:JPEGHA]{JPEG\_HA}} & \textbf{\hyperref[fielddesc:JPEGVA]{JPEG\_VA}}\\ \hline
                YUV444 & Multiples of 8 & Multiples of 8 \\ \hline
                YUV422 & Multiples of 16 & Multiples of 8 \\ \hline
                YUV420 & Multiples of 16 & Multiples of 16 \\ \hline
                GRAY & Multiples of 8 & Multiples of 8 \\ \hline
            \end{longtable}
        \end{itemize}
    \end{itemize}
    \item Configure 2D DMA (for configuration details and related concepts, see Chapter \ref{mod:2ddma} \textit{\nameref{mod:2ddma}}.)
    \begin{enumerate}
        \item Configure the linked list of the 2D DMA TX channel.
        \begin{itemize}
            \item Set 2DEN to 0 to enable the 1D function.
            \item Configure the Buffer address pointer as the starting address where the bitstream to be decoded is stored.
            \item Configure size as the number of bytes in the space to store the bitstream to be decoded.
            \item Configure mod as 0. mod is invalid when 2DEN is 0.
        \end{itemize}
        \item Configure the linked list of 2D DMA RX channel.
        \begin{itemize}
            \item Set 2DEN to 1 to enable 2D function.
            \item Configure the Buffer address pointer as the starting address where the decoded image will be stored.
            \item Configure pbyte as the number of bytes per pixel after decoding and 2D DMA color space conversion.
            \item Configure HA as the output decoded image width, VA as the output decoded image height, hb as the number of pixels per image block in the horizontal direction, and vb as the number of pixels per image block in the vertical direction.
            \item Configure mod as 1, which means continuous writing of image blocks of hb × vb size.
            \item Configure (X, Y) as the coordinate of the first pixel in the starting image block. According to the decoded image format, hb and vb must meet the restrictions in Table \ref{tab:de_hb_vb} \textit{\nameref{tab:de_hb_vb}}:
        \begin{longtable}{ | L{4cm} | L{3cm} | L{3cm} | }
        \caption{JPEG Decoder hb and vb Configuration} \label{tab:de_hb_vb}
        \\ \hline
        \rowcolor{lightgray}
        \textbf{Format of Decoded Image}  &  \textbf{hb}  &  \textbf{vb}\\ \hline
        YUV444 &  Multiples of 8 &  Multiples of 8  \\ \hline
        YUV422 &  Multiples of 16 &  Multiples of 8  \\ \hline
        YUV420 &  Multiples of 16 &  Multiples of 16  \\ \hline
        GRAY &  Multiples of 8 &  Multiples of 8  \\ \hline
        \end{longtable}
        \end{itemize}
        \item Connect 2D DMA channels to JPEG codec:
        \begin{itemize}
            \item Connect the TX channel\regindex{n} to the JPEG codec by configuring \hyperref[fielddesc:DMA2DOUTPERISELCHN]{DMA2D\_OUT\_PERI\_SEL\_CH\regindex{n}} to 0;
            \item Connect the RX channel\regindex{n} to the JPEG codec by configuring \hyperref[fielddesc:DMA2DINPERISELCHN]{DMA2D\_IN\_PERI\_SEL\_CH\regindex{n}} to 0.
        \end{itemize}
        \item Reset 2D DMA channels:
        \begin{itemize}
            \item 2D DMA TX channel\regindex{n}: set \hyperref[fielddesc:DMA2DOUTRSTCHN]{DMA2D\_OUT\_RST\_CH\regindex{n}} to 1 to reset 2D DMA TX channel\regindex{n}, then set \hyperref[fielddesc:DMA2DOUTRSTCHN]{DMA2D\_OUT\_RST\_CH\regindex{n}} to 0 to release the reset of 2D DMA TX channel\regindex{n}.
            \item 2D DMA RX channel\regindex{n}: set \hyperref[fielddesc:DMA2DINRSTCHN]{DMA2D\_IN\_RST\_CH\regindex{n}} to 1 to reset 2D DMA RX channel\regindex{n}, then set \hyperref[fielddesc:DMA2DINRSTCHN]{DMA2D\_IN\_RST\_CH\regindex{n}} to 0 to release the reset of 2D DMA RX channel\regindex{n}.
        \end{itemize}
        \item Select the burst length of 2D DMA channels:
        \begin{itemize}
            \item Configure \hyperref[fielddesc:DMA2DOUTMEMBURSTLENGTHCHN]{DMA2D\_OUT\_MEM\_BURST\_LENGTH\_CH\regindex{n}} to select the burst length of 2D DMA TX channel\regindex{n}.
            \item Configure \hyperref[fielddesc:DMA2DINMEMBURSTLENGTHCHN]{DMA2D\_IN\_MEM\_BURST\_LENGTH\_CH\regindex{n}} to select the burst length of 2D DMA RX channel\regindex{n}.
        \end{itemize}
        \item Select 2D DMA receive image block size by configuring \hyperref[fielddesc:DMA2DINMACROBLOCKSIZECHN]{DMA2D\_IN\_MACRO\_BLOCK\_SIZE\_CH\regindex{n}} according to the format of the decoded image. See details in Table \ref{tab:de_block_size} \textit{\nameref{tab:de_block_size}}:
        \begin{itemize}
            \item 0: 8 × 8
            \item 1: 16 × 8
            \item 2: 16 × 16
        \end{itemize}
        \begin{longtable}{ | c | c | }
        \caption{\hyperref[fielddesc:DMA2DINMACROBLOCKSIZECHN]{DMA2D\_IN\_MACRO\_BLOCK\_SIZE\_CH\regindex{n}} Configuration} \label{tab:de_block_size}
        \\ \hline
        \rowcolor{lightgray}
        \textbf{Format of Decoded Image} & \textbf{\hyperref[fielddesc:DMA2DINMACROBLOCKSIZECHN]{DMA2D\_IN\_MACRO\_BLOCK\_SIZE\_CH\regindex{n}}}  \\ \hline
        YUV444 &   0\\ \hline
        YUV422 &   1\\ \hline
        YUV420 &   2\\ \hline
        GRAY &    0\\ \hline
        \end{longtable}
        \item Enable the reorder function to improve bandwidth utilization by setting \hyperref[fielddesc:DMA2DINREORDERENCH0]{DMA2D\_IN\_REORDER\_EN\_CH0} to 1. Note that this function is only available for 2D DMA RX channel 0, not for any other RX channels.
        \item Select whether to scramble the pixel order of the decoded image before 2D DMA color space conversion by configuring \hyperref[fielddesc:DMA2DINSCRAMBLESELPRECH0]{DMA2D\_IN\_SCRAMBLE\_SEL\_PRE\_CH0}:
        \begin{itemize}
            \item 0: BYTE2-1-0
            \item 1: BYTE2-0-1
            \item 2: BYTE1-0-2
            \item 3: BYTE1-2-0
            \item 4: BYTE0-2-1
            \item 5: BYTE0-1-2
        \end{itemize}
        Configuring \hyperref[fielddesc:DMA2DINSCRAMBLESELPRECH0]{DMA2D\_IN\_SCRAMBLE\_SEL\_PRE\_CH0} to 5 swaps the pixel order, for example, from YUV444 output by the JPEG decoder to VUY444. This function is available only on 2D DMA RX channel 0, not on other RX channels.
        \item Configure \hyperref[fielddesc:DMA2DINCOLORINPUTSELCH0]{DMA2D\_IN\_COLOR\_INPUT\_SEL\_CH0}, \hyperref[fielddesc:DMA2DINCOLOR3BPROCENCH0]{DMA2D\_IN\_COLOR\_3B\_PROC\_EN\_CH0}, and \hyperref[fielddesc:DMA2DINCOLOROUTPUTSELCH0]{DMA2D\_IN\_COLOR\_OUTPUT\_SEL\_CH0} to select the color conversion method. See Table \ref{tab:de_csc} \textit{\nameref{tab:de_csc}}:
        \begin{longtable}{ | l | c | c | c | }
        \caption{2D DMA Color Space Conversion Configuration} \label{tab:de_csc}
        \\ \hline
        \rowcolor{lightgray}
        \textbf{Color Space Conversion Method} & \textbf{INPUT\_SEL\_CH0}  &  \textbf{3B\_PROC\_EN\_CH0} &  \textbf{OUTPUT\_SEL\_CH0}  \\ \hline
        YUV420 -> RGB &  0  &  1  &  1 \\ \hline
        YUV422 -> RGB &  0  &  1  &  1 \\ \hline
        YUV444 -> RGB &  2  &  1  &  1 \\ \hline
        YUV444 (only reverse the pixel order) &  2  &  0  &  1 \\ \hline
        No color space conversion &  7  &  N/A  &  N/A \\ \hline
        \end{longtable}
        This function is available only on 2D DMA RX channel 0, not on other RX channels.
        \item Configure the parameters for the color space conversion formula, including \hyperref[fielddesc:DMA2DINCOLORPARAMH0CH0]{DMA2D\_IN\_COLOR\_PARAM\_H0\_CH0}, \hyperref[fielddesc:DMA2DINCOLORPARAMH1CH0]{DMA2D\_IN\_COLOR\_PARAM\_H1\_CH0}, \hyperref[fielddesc:DMA2DINCOLORPARAMM0CH0]{DMA2D\_IN\_COLOR\_PARAM\_M0\_CH0}, \hyperref[fielddesc:DMA2DINCOLORPARAMM1CH0]{DMA2D\_IN\_COLOR\_PARAM\_M1\_CH0}, \hyperref[fielddesc:DMA2DINCOLORPARAML0CH0]{DMA2D\_IN\_COLOR\_PARAM\_L0\_CH0}, and \hyperref[fielddesc:DMA2DINCOLORPARAML1CH0]{DMA2D\_IN\_COLOR\_PARAM\_L1\_CH0}. This function is available only on 2D DMA RX channel 0, not on other RX channels.
        \item Select whether to reverse the pixel order of the image after 2D DMA color space conversion by configuring \hyperref[fielddesc:DMA2DINSCRAMBLESELPOSTCH0]{DMA2D\_IN\_SCRAMBLE\_SEL\_POST\_CH0}:
        \begin{itemize}
            \item 0: BYTE2-1-0
            \item 1: BYTE2-0-1
            \item 2: BYTE1-0-2
            \item 3: BYTE1-2-0
            \item 4: BYTE0-2-1
            \item 5: BYTE0-1-2
        \end{itemize}
        Setting \hyperref[fielddesc:DMA2DINSCRAMBLESELPOSTCH0]{DMA2D\_IN\_SCRAMBLE\_SEL\_POST\_CH0} to 5 reverses the pixel order, for example, from RGB to BGR after 2D DMA color space conversion. This function is available only on 2D DMA RX channel 0, not on other RX channels.
        \item Configure 2D DMA channel linked list addresses:
        \begin{itemize}
            \item 2D DMA TX channel: \hyperref[fielddesc:DMA2DOUTLINKADDRCHN]{DMA2D\_OUTLINK\_ADDR\_CH\regindex{n}}
            \item 2D DMA RX channel: \hyperref[fielddesc:DMA2DINLINKADDRCHN]{DMA2D\_INLINK\_ADDR\_CH\regindex{n}}
        \end{itemize}
    \end{enumerate}
    \item Enable interrupt sources:
    \begin{itemize}
        \item \hyperref[regdesc:DMA2DOUTINTENACHNREG]{DMA2D\_OUT\_INT\_ENA\_CH\regindex{n}\_REG}
        \item \hyperref[regdesc:DMA2DININTENACHNREG]{DMA2D\_IN\_INT\_ENA\_CH\regindex{n}\_REG}
        \item \hyperref[regdesc:JPEGINTENAREG]{JPEG\_INT\_ENA\_REG}
    \end{itemize}
    \item Start the transmission of 2D DMA channels:
    \begin{itemize}
        \item 2D DMA TX channel\regindex{n}: set \hyperref[fielddesc:DMA2DOUTLINKSTARTCHN]{DMA2D\_OUTLINK\_START\_CH\regindex{n}} to 1 and then to 0.
        \item 2D DMA RX channel\regindex{n}: set \hyperref[fielddesc:DMA2DINLINKSTARTCHN]{DMA2D\_INLINK\_START\_CH\regindex{n}} to 1 and then to 0.
    \end{itemize}
    \item Start JPEG codec decoding by setting the \hyperref[fielddesc:JPEGJPEGSTART]{JPEG\_JPEG\_START} field.
    \item Wait until DMA2D\_IN\_SUC\_EOF\_CH\regindex{n}\_INT becomes 1, indicating that the decoded image has been completely written to memory.
\end{enumerate}

\subsection{Reset}

Depending on the scenario, users can \textbf{reset} all or part of the JPEG codec modules during encoding or decoding:
\begin{itemize}
    \item Reset all modules (including all RAM, FIFO, and state machines): set \hyperref[fielddesc:JPEGSOFTRST]{JPEG\_SOFT\_RST} to 1. Register configuration is not reset.
    \item Reset all RAM and FIFO (for example, when changing the quantization coefficient table or Huffman table): set \hyperref[fielddesc:JPEGFIFORST]{JPEG\_FIFO\_RST} to 1.
    \item Reset all state machines (for example, when terminating the current encoding or decoding process): set \hyperref[fielddesc:JPEGFSMRST]{JPEG\_FSM\_RST} to 1.
\end{itemize}
