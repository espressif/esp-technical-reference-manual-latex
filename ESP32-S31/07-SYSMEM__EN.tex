\chapter{System and Memory}
\label{mod:sysmem}

\section{Overview}
\chipname{} has an ultra-low-power and highly integrated system with:
\begin{itemize}
    \item a high-performance dual-core 32-bit RISC-V processor (HP CPU), five-stage pipeline architecture, clock frequency up to 320 MHz
    \item a low-power single-core 32-bit RISC-V processor (LP CPU), two-stage pipeline architecture, clock frequency up to 40 MHz
\end{itemize}

All internal memory, external memory, and peripherals are distributed on the HP CPU and LP CPU buses.

\section{Features}

\begin{itemize}
    \item {\bfseries Address Space}
        \begin{itemize}
    	    \item 864 KB of internal memory address space, accessible by the instruction bus or data bus
    	    \item 2464 KB of peripheral address space
    	    \item 320 MB of virtual address space for external memory, accessible by the instruction bus or data bus
    	    \item 512 KB of internal DMA address space
                \item 320 MB of external DMA address space
        \end{itemize}
    \item {\bfseries Internal Memory}
        \begin{itemize}
            \item 320 KB of ROM
	        \item 512 KB of HP SRAM
	        \item 32 KB of LP SRAM
	    \end{itemize}
    \item {\bfseries External Memory}
        \begin{itemize}
            \item Up to 256 MB of external flash
            \item Up to 64 MB of external RAM
	    \end{itemize}
    \item \textbf{Peripheral Space}
        \begin{itemize}
           \item Multiple modules/peripherals (see Table \ref{tab:sysmem-base-address})
        \end{itemize}
    \item {\bfseries GDMA}
        \begin{itemize}
            \item 6 modules/peripherals support HP GDMA-AHB
            \item 2 modules/peripherals support LP GDMA-AHB
            \item 7 modules/peripherals support GDMA-AXI
        \end{itemize}
\end{itemize}

\section{Functional Description}

\subsection{Address Mapping}

Figure \ref{fig:sysmem-address-mapping-structure} illustrates the system structure and address mapping. All the non-reserved addresses are accessible via both the instruction bus and the data bus, meaning that the instruction bus and the data bus share the same address space. Both the data bus and instruction bus of the HP CPU and LP CPU are little-endian. All buses have a 32-bit data width. HP CPU and LP CPU can access data via the data bus using single-byte, double-byte, and four-byte accesses.

The HP CPU has the following access capabilities:
\begin{itemize}
\item Direct access to internal memory via both the data bus and instruction bus
  \begin{itemize}
        \item 512 KB HP SRAM (0x2F00\_0000 \verb+~+ 0x2F07\_FFFF)
        \item 32 KB LP SRAM  (0x2E00\_0000 \verb+~+ 0x2E00\_7FFF)
    \end{itemize}
\item Access to internal memory via \hyperlink{par:rom}{ROM-Cache}
    \begin{itemize}
        \item 320 KB ROM (0x2F80\_0000 \verb+~+ 0x2F84\_FFFF)
    \end{itemize}

\begin{tiplisting}
Software can access the ROM addresses in a cacheable or non-cacheable manner. Cacheable access is performed through the cache; non-cacheable access is direct access without going through the cache. Whether the access is cacheable or non-cacheable is controlled by the CPU PMA (Physical Memory Attribution).
\end{tiplisting}
\item Access to external memory through the cache, with virtual addresses mapped to the physical address space of the external memory through the MMU
    \begin{itemize}
        \item Up to 256 MB external flash (0x4000\_0000 \verb+~+ 0x4FFF\_FFFF)
        \item Up to 64 MB external RAM (0x5000\_0000 \verb+~+ 0x53FF\_FFFF)
    \end{itemize}
\item Direct access to external memory via the data bus (slower, usually used for debugging), with virtual addresses mapped to the physical address space of the external memory through the MMU
    \begin{itemize}
        \item Up to 256 MB external flash. The address range for direct access is 0xA000\_0000 \verb+~+ 0xAFFF\_FFFF. After the HP CPU issues an address in this range, the address is first mapped to 0x4000\_0000 \verb+~+ 0x4FFF\_FFFF.
        \item Up to 64 MB external RAM. The address range for direct access is 0xC000\_0000 \verb+~+ 0xC3FF\_FFFF. After the HP CPU issues an address in this range, the address is first mapped to 0x5000\_0000 \verb+~+ 0x53FF\_FFFF.
    \end{itemize}
\item Direct access to modules/peripherals via the data bus, including:
    \begin{itemize}
        \item HP Peripherals
        \item LP Peripherals
        \item CPU Peripherals
        \item Debug Peripherals
    \end{itemize}
\end{itemize}

The LP CPU has the following access capabilities:
\begin{itemize}
    \item Direct access to HP SRAM and LP SRAM via both the data bus and instruction bus
     \begin{itemize}
        \item 512 KB HP SRAM (0x2F00\_0000 \verb+~+ 0x2F07\_FFFF)
        \item 32 KB LP SRAM  (0x2E00\_0000 \verb+~+ 0x2E00\_7FFF)
    \end{itemize}
\item Direct access to external memory via the data bus, with virtual addresses mapped to the physical address space of the external memory through the MMU
    \begin{itemize}
        \item Up to 256 MB external flash (0x4000\_0000 \verb+~+ 0x4FFF\_FFFF)
        \item Up to 64 MB external RAM (0x5000\_0000 \verb+~+ 0x53FF\_FFFF)
    \end{itemize}
    \item Direct access to modules/peripherals via the data bus, including:
    \begin{itemize}
        \item HP Peripherals
        \item LP Peripherals
        \item CPU Peripherals
        \item Debug Peripherals
    \end{itemize}
\end{itemize}

\subsection{Internal Memory}
\label{para:sysmem-internal-memory}

\chipname{} internal memory includes the following three types:

\begin{itemize}
    \item ROM (320 KB): A read-only memory that is not programmable and can be accessed only by the HP CPU. It stores the ROM code of low-level system software and read-only data.
    \item HP SRAM (512 KB): A volatile memory that can respond to access requests from the HP CPU and LP CPU. The access latency for the HP CPU is typically one HP CPU clock cycle.
    \item LP SRAM (32 KB): Implemented as static RAM (SRAM) and therefore also volatile. However, in Deep-sleep mode, data stored in the LP SRAM is not lost. The LP SRAM can be accessed by the HP CPU and LP CPU and is usually used to store program instructions and data that need to be retained in sleep mode.
\end{itemize}


\subsubsection{ROM}
\label{par:rom}

The ROM is 320 KB and read-only. As shown in Table \ref{tab:sysmem-memory}, the HP CPU can access this memory through the instruction bus or data bus address range 0x2F80\_0000 \verb+~+ 0x2F84\_FFFF via ROM-Cache (see Figure \ref{fig:sysmem-rom-cache-arch}). The access type can be set to non-cacheable or cacheable through the PMA.

The \chipname{} ROM-Cache is two-way set associative, with a capacity of 4 KB and a block size (cache line) of 64 B. Both the instruction bus and the data bus can access the ROM-Cache at the same time, and the ROM-Cache responds to one of them through arbitration. When a ROM-Cache miss occurs, the ROM-Cache controller initiates a request to the ROM.

\subsubsection{HP SRAM}
\label{other:sysmem-internal-sram-0}

The HP SRAM is 512 KB and is readable and writable. As shown in Table \ref{tab:sysmem-memory}, the HP CPU and LP CPU can access this memory through the data bus or instruction bus.


\subsubsection{LP SRAM}

The LP SRAM is 32 KB and is a readable and writable SRAM. As shown in Table \ref{tab:sysmem-memory}, the HP CPU and LP CPU can access this memory through the shared data bus and instruction bus address range 0x2E00\_0000 \verb+~+ 0x2E00\_7FFF.


\subsection{External Memory}
\label{para:sysmem-external-memory}

\chipname{} connects external flash and external RAM through two independent MSPI controllers (Flash MSPI and PSRAM MSPI). Flash MSPI supports SPI, Dual SPI, Quad SPI, QPI, and other interfaces, and PSRAM MSPI supports Octal SPI, OPI, and other interfaces. \chipname{} also supports the following security mechanisms to protect data stored by users in external flash and RAM:
\begin{itemize}
    \item Hardware manual encryption and automatic decryption based on XTS-AES, to protect programs and data in external flash.
    \item Automatic encryption and decryption based on XTS-AES, to protect data in external RAM.
\end{itemize}


\subsubsection{External Memory Address Mapping}

The HP CPU can access external memory in two ways:
\begin{itemize}
    \item Through the cache
    \item Direct access without going through the cache (slower, usually used for debugging)
\end{itemize}

For external flash:
\begin{itemize}
    \item The address range for cache access is 0x4000\_0000 \verb+~+ 0x4FFF\_FFFF.
    \item The address range for direct access is 0xA000\_0000 \verb+~+ 0xAFFF\_FFFF. After the HP CPU issues an address in this range, the address is first mapped to 0x4000\_0000 \verb+~+ 0x4FFF\_FFFF.
\end{itemize}
GDMA-AXI and other peripherals can also access external flash. The Memory Management Unit (MMU) maps the addresses of the HP CPU and GDMA-AXI peripherals (0x4000\_0000 \verb+~+ 0x4FFF\_FFFF) to the physical address of external flash. The MMU page size supports four configurations: 32 KB, 64 KB, 128 KB, and 256 KB. With this address mapping, \chipname{} supports up to 256 MB of off-chip flash.

For external RAM:
\begin{itemize}
    \item The address range for cache access is 0x5000\_0000 \verb+~+ 0x53FF\_FFFF.
    \item The address range for direct access is 0xC000\_0000 \verb+~+ 0xC3FF\_FFFF. After the HP CPU issues an address in this range, the address is first mapped to 0x5000\_0000 \verb+~+ 0x53FF\_FFFF.
\end{itemize}
GDMA-AXI and other peripherals can also access external RAM. The MMU maps the addresses of the HP CPU and GDMA-AXI peripherals (0x5000\_0000 \verb+~+ 0x53FF\_FFFF) to the physical address of external RAM. The MMU page size supports four configurations: 8 KB, 16 KB, 32 KB, and 64 KB. With this address mapping, \chipname{} supports up to 64 MB of off-chip RAM.

Note that the instruction bus and the data bus share the above address spaces (256 MB for external flash and 64 MB for external RAM).

\subsubsection{Cache}

As shown in Figure \ref{fig:sysmem-cache-arch}, \chipname{} uses a private instruction cache for each HP CPU core (HP CPU0 and HP CPU1), while the two HP CPU cores share one data cache. The instruction cache is 32 KB, with a block size of 64 B, 1 bank, and two-way set associative. The data cache is 64 KB, with a block size of 64 B, 4 banks, and two-way set associative. When a cache miss occurs, the cache controller initiates a request to the external memory.

\subsubsection{Cache Operations}

\chipname{} cache supports the following operations:

\begin{enumerate}
\item \textbf{Write-back}
\begin{itemize}
    \item Clears dirty bits in the tag memory and updates new data to external memory.
    \item After the write-back operation, the new data is updated to external memory.
    \item Users can choose whether to invalidate the data in the cache.
    \item If invalidation is not selected, the HP CPU can read/write data directly from/to the cache without a cache miss.
    \item This operation includes two types:
    \begin{itemize}
    \item Specified-area write-back: performed only on data in the specified area of the cache. The minimum unit is one cache block.
    \item All-cache write-back: performed on all data in the cache.
    \end{itemize}
\end{itemize}

\item \textbf{Clean}
\begin{itemize}
    \item Clears dirty bits in the tag memory without updating new data to external memory.
    \item After the clean operation, old data remains in external memory, while the cache retains the new data but is unaware that the data is new.
    \item The HP CPU can then read/write the data directly from/to the cache without a cache miss.
    \item This operation includes two types:
    \begin{itemize}
    \item Specified-area clean: performed only on data in the specified area of the cache. The minimum unit is one cache block.
    \item All-cache clean: performed on all data in the cache.
    \end{itemize}
\end{itemize}

\item \textbf{Invalidate}
\begin{itemize}
    \item Clears valid bits in the tag memory to remove valid data from the cache.
    \item After this operation, the deleted data exists only in external memory.
    \item If the HP CPU subsequently accesses the data, it needs to access external memory.
    \item This operation includes two types:
    \begin{itemize}
    \item Specified-area invalidate: performed only on data in the specified area of the cache. The minimum unit is one cache block.
    \item All-cache invalidate: performed on all data in the cache.
    \end{itemize}
\end{itemize}

\item \textbf{Preload}
\begin{itemize}
    \item Loads instructions and data into the cache in advance.
    \item The minimum unit of a preload operation is one cache block.
    \item This operation includes two types:
    \begin{itemize}
    \item Manual-Preload: hardware prefetches a contiguous segment of data based on the virtual address specified by software.
    \item Auto-Preload: hardware automatically prefetches a contiguous segment of data based on the current hit/miss address (depending on configuration).
    \end{itemize}
\end{itemize}

\item \textbf{Lock/Unlock}
\begin{itemize}
    \item Protects data in the cache from being replaced.
    \item This lock operation includes two types:
    \begin{itemize}
    \item Prelock: when filling missing data into the cache, if the data falls in the specified area, the cache locks the data; data outside the specified area is not locked.
    \item Manual lock: checks data in the cache and locks data that falls in the specified area; data outside the specified area is not locked.
    \end{itemize}
    \item When a miss occurs, the cache preferentially replaces data in the unlocked way, so data in the locked area remains in the cache.
    \item However, when all ways are locked, the cache performs normal replacement as if no ways were locked.
    \item Unlocking is the reverse of locking and can only be done manually.
    \item Note that write-back, clean, and specified-area invalidate operations apply only to unlocked data. To perform these operations on locked data, unlock the data first.

\end{itemize}
\end{enumerate}


\subsection{GDMA Address Space}

\chipname{} supports HP/LP AHB General DMA (HP/LP GDMA-AHB) and HP AXI General DMA (HP GDMA-AXI), all of which can provide direct memory access services. In addition, host modules such as High-Speed USB 2.0, RISC-V Trace, and 2D-DMA also have built-in DMA functions and can likewise provide direct memory access services.

All of the above DMA-capable host modules can access:
\begin{itemize}
    \item HP SRAM (0x2F00\_0000 \verb+~+ 0x2F07\_FFFF)
    \item LP SRAM  (0x2E00\_0000 \verb+~+ 0x2E00\_7FFF)
    \item External flash (0x4000\_0000 \verb+~+ 0x4FFF\_FFFF)
    \item External RAM (0x5000\_0000 \verb+~+ 0x53FF\_FFFF)
    \end{itemize}

\begin{tiplisting}
When using DMA to access any memory, the corresponding access permission must be obtained; otherwise the access will fail. For more information about permission management, please refer to Chapter \ref{mod:permctrl} \textit{\nameref{mod:permctrl}}.
\end{tiplisting}
