\hypertarget{dma}{}
\chapter{GDMA Controller (GDMA-AHB, GDMA-AXI)}
\label{mod:dma}


\section{Overview}

General Direct Memory Access (GDMA) provides high-speed data transfer between peripherals and memory, and between memory and memory. With GDMA, software can transfer data without CPU intervention, reducing CPU load and improving system efficiency.

\chipname{} has two types of GDMA controllers that directly access the AHB bus and the AXI bus, hereinafter referred to as GDMA-AHB and GDMA-AXI. Depending on the system, GDMA-AHB is further divided into GDMA-AHB-HP and GDMA-AHB-LP for high-performance and low-power systems. GDMA channels are shared among peripherals that support GDMA. Users can assign a channel to any such peripheral.
\begin{itemize}
    \item GDMA-AHB-HP: 10 independent channels, including 5 transmit channels and 5 receive channels. Supported peripherals include UHCI, I2S, RMT, Audio Sample Rate Converter (ASRC), and CORDIC accelerator.
    \item GDMA-AHB-LP: 4 independent channels, including 2 transmit channels and 2 receive channels. Supported peripherals include ADC and DAC.
    \item GDMA-AXI: 6 independent channels, including 3 transmit channels and 3 receive channels. Supported peripherals include LCD, CAM, two general-purpose SPIs, PARLIO, AES, and SHA.
\end{itemize}

GDMA-AHB-HP and GDMA-AHB-LP are functionally identical, differing only in the number of channels and supported peripherals. The following description uses GDMA-AHB-HP as the reference, and everything applies equally to GDMA-AHB-LP by replacing the register prefix \texttt{AHB\_DMA\_} with \texttt{LP\_AHB\_DMA\_}. Unless otherwise specified, GDMA-AHB refers to both GDMA-AHB-HP and GDMA-AHB-LP, and GDMA refers to both GDMA-AHB and GDMA-AXI.

On \chipname{}, both GDMA-AHB and GDMA-AXI can access internal and external memory. GDMA-AHB and GDMA-AXI use configurable priority and weight arbitration to meet the bandwidth requirements of different peripherals.





\section{Features}

GDMA-AHB and GDMA-AXI have the following common features:

\begin{itemize}
    \item Data transfer in bytes with software-programmable transfer length
    \item Access via any address and size
    \item Linked list
    \item Software-configurable peripheral selection for each channel
    \item Configurable channel priority and weight arbitration
    \item Memory-to-memory transfer
\end{itemize}

GDMA-AHB features:

\begin{itemize}
    \item Architecture: AHB bus architecture
    \item Channels: GDMA-AHB-HP has five transmit channels and five receive channels; GDMA-AHB-LP has two transmit channels and two receive channels
    \item Alignment requirements:
        \begin{itemize}
            \item Descriptor address: 1-word aligned
            \item Data address and length:
                \begin{itemize}
                    \item Internal memory and non-encrypted external memory: no requirements
                    \item Encrypted external memory (only accessed by GDMA-AHB-HP, not GDMA-AHB-LP): 16-byte aligned
                \end{itemize}
        \end{itemize}
    \item INCR4, INCR8, or INCR16 burst transfer when accessing memory
\end{itemize}

GDMA-AXI features:

\begin{itemize}
    \item Architecture: AXI bus architecture, supporting out-of-order transfers with a depth of 8 and outstanding transfers with a depth of 8
    \item Channels: three transmit channels and three receive channels
    \item Alignment requirements:
        \begin{itemize}
            \item Descriptor address: 2-word aligned
            \item Data address and length:
                \begin{itemize}
                    \item Internal memory and non-encrypted external memory: no requirements
                    \item Encrypted external memory: 16-byte aligned
                \end{itemize}
        \end{itemize}
    \item Burst transfer when accessing memory, with burst length configurable as 1, 2, 4, 8, or 16 beats
    \item Interrupt response mechanism for linked list switching
\end{itemize}


\section{Architecture}

The GDMA controller and the CPU data bus use the same address space to access memory. All modules on \chipname{} that require high-speed data transfer support GDMA. Figure \ref{fig:gdma-controller} shows the basic architecture of the GDMA controller.

\begin{figure}[H]
\input{\modulefiles/figures/gdma_arch.tex}
\centering
\caption{GDMA Controller Architecture}
\label{fig:gdma-controller}
\end{figure}

Both GDMA-AHB and GDMA-AXI have a fixed number of transfer channels. The number of transmit channels equals the number of receive channels. Each channel can connect to a different peripheral, so channel resources are shared among peripherals.

GDMA-AHB and GDMA-AXI read data from or write data to internal or external memory via the AHB bus or the AXI bus respectively. Before transferring data over the bus, GDMA arbitrates read and write requests from each channel using a configurable arbitration mechanism. For the memory address ranges available to GDMA, see Chapter \ref{mod:sysmem} \textit{\nameref{mod:sysmem}}.

Software uses the GDMA controller through linked lists. GDMA-AHB linked lists are stored in internal memory; GDMA-AXI linked lists are stored in internal or external memory. These linked lists include outlink\textcolor{red}{\it{n}} and inlink\textcolor{red}{\it{n}}. In this chapter, \textcolor{red}{\it{n}} denotes the physical channel number.

GDMA reads linked lists from memory, then sends data from the corresponding memory according to outlink\textcolor{red}{\it{n}}, or stores received data in the specified memory address space according to inlink\textcolor{red}{\it{n}}.


\section{Functional Description}

\subsection{Linked List}

\begin{figure}[H]
\includegraphics[width=1\textwidth]{\modulefiles/figures/link_strut}
\centering
\caption{Structure of a Linked List}
\label{fig:gdma-link-descriptor}
\end{figure}

Figure \ref{fig:gdma-link-descriptor} shows the structure of a linked list. An outlink and an inlink have the same structure. A linked list consists of one or more descriptors; each descriptor has three words. Store linked lists in memory so that GDMA can use them. The descriptor fields are defined as follows:

\begin{itemize}
    \item owner (DW0) [31]: Specifies who may access the buffer that this descriptor points to.\\
    0: The CPU may access the buffer. \\
    1: The GDMA controller may access the buffer.\\
    After GDMA finishes using the buffer, hardware automatically clears this bit in a receive descriptor. For a transmit descriptor, hardware clears this bit automatically only if \hyperref[fielddesc:AHBDMAOUTAUTOWRBACKCHN]{AHB/AXI\_DMA\_OUT\_AUTO\_WRBACK\_CH\regindex{n}} is set to 1. Software can disable automatic clearing by setting \hyperref[fielddesc:AHBDMAOUTLOOPTESTCHN]{AHB/AXI\_DMA\_OUT\_LOOP\_TEST\_CH\regindex{n}} or \hyperref[fielddesc:AHBDMAINLOOPTESTCHN]{AHB/AXI\_DMA\_IN\_LOOP\_TEST\_CH\regindex{n}}. When software loads a linked list, set this bit to 1.\\
    {\bfseries Note:} In this chapter, registers prefixed with AHB/AXI\_DMA\_OUT belong to transmit channels; registers prefixed with AHB/AXI\_DMA\_IN belong to receive channels.
    \item suc\_eof (DW0) [30]: Specifies whether the AHB/AXI\_DMA\_IN\_SUC\_EOF\_CH\regindex{n}\_INT or AHB/AXI\_DMA\_OUT\_EOF\_CH\regindex{n}\_INT interrupt is triggered after the data corresponding to this descriptor is transferred.\\
    0: No interrupt is triggered after the current descriptor is transferred successfully.\\
    1: An interrupt is triggered after the current descriptor is transferred successfully.\\
    For receive descriptors, software clears this bit to 0; hardware sets it to 1 after receiving data that contains the EOF flag.\\
    For transmit descriptors, software sets this bit to 1 as needed.\\
    If software sets this bit to 1, GDMA includes the EOF flag in the data sent to the peripheral, indicating that this data segment has ended.
    \item reserved (DW0) [29]: Reserved. The value of this bit does not matter.
    \item err\_eof (DW0) [28]: Specifies whether the received data has errors.\\
    0: The received data does not have errors.\\
    1: The received data has errors.\\
    This bit applies only when UHCI or PARLIO receives data via GDMA. Hardware sets this bit to 1 when it detects an error in the data segment corresponding to a descriptor.
    \item reserved (DW0) [27:24]: Reserved.
    \item length (DW0) [23:12]: Specifies the number of valid bytes in the buffer that this descriptor points to. In a transmit descriptor, software writes this field to indicate how many bytes to read from the buffer. In a receive descriptor, hardware writes this field automatically to indicate how many valid bytes are stored in the buffer.
    \item size (DW0) [11:0]: Specifies the size of the buffer that this descriptor points to.
    \item buffer address pointer (DW1): Address of the buffer.
    \item next descriptor address (DW2): Address of the next descriptor. If the current descriptor is the last one, this value is 0. For GDMA-AHB, this field can only point to the internal memory space; for GDMA-AXI, this field can point to the internal or external memory space.
        \begin{tiplisting}
            GDMA-AHB descriptor addresses must be 4-byte aligned; GDMA-AXI descriptor addresses must be 8-byte aligned.
        \end{tiplisting}
\end{itemize}

When GDMA receives data, if the received data length is smaller than the buffer size specified by the current descriptor, the next descriptor does not use the remaining space in that buffer.

\subsection{Peripheral-to-Memory and Memory-to-Peripheral Data Transfer}

A TX channel transfers data from the specified memory region to a peripheral transmitter via outlink\textcolor{red}{\it{n}}. An RX channel transfers data received by a peripheral to the specified memory region via inlink\textcolor{red}{\it{n}}.

\subsection{Memory-to-Memory Data Transfer}

The GDMA controller supports memory-to-memory data transfer. Such data transfer is performed by setting \hyperref[fielddesc:AHBDMAMEMTRANSENCHN]{AHB/AXI\_DMA\_MEM\_TRANS\_EN\_CH\regindex{n}} to connect the output of TX channel \textcolor{red}{\it{n}} to the input of RX channel \textcolor{red}{\it{n}}.

A TX channel is paired only with the RX channel of the same number for memory-to-memory transfer. \hyperref[fielddesc:AHBDMAPERIINSELCHN]{AHB/AXI\_DMA\_PERI\_IN\_SEL\_CH\regindex{n}} and \hyperref[fielddesc:AHBDMAPERIOUTSELCHN]{AHB/AXI\_DMA\_PERI\_OUT\_SEL\_CH\regindex{n}} must be configured to the same value corresponding to ``Dummy".

All 5 channels of GDMA-AHB-HP and 2 channels of GDMA-AHB-LP support memory-to-memory data transfers. The ID recorded by \hyperref[fielddesc:AHBDMAAHBINFRESPERRID]{AHB\_DMA\_AHBINF\_RESP\_ERR\_ID} is fixed: ID 16 indicates memory-to-memory transfer on GDMA-AHB channel 0; ID 17 indicates memory-to-memory transfer on GDMA-AHB channel 1, and so on.

\subsection{Enabling GDMA}

Software uses the GDMA controller through linked lists.

For data reception, software loads a receive linked list and prepares to receive data. Configure \hyperref[fielddesc:AHBDMAINLINKADDRCHN]{AHB/AXI\_DMA\_INLINK\_ADDR\_CH\regindex{n}} to point to the first receive descriptor, then set \hyperref[fielddesc:AHBDMAINLINKSTARTCHN]{AHB/AXI\_DMA\_INLINK\_START\_CH\regindex{n}} to start GDMA.

For data transmission, software loads a transmit linked list and prepares data to transmit. Configure \hyperref[fielddesc:AHBDMAOUTLINKADDRCHN]{AHB/AXI\_DMA\_OUTLINK\_ADDR\_CH\regindex{n}} to point to the first transmit descriptor, then set \hyperref[fielddesc:AHBDMAOUTLINKSTARTCHN]{AHB/AXI\_DMA\_OUTLINK\_START\_CH\regindex{n}} to start GDMA. Hardware automatically clears \hyperref[fielddesc:AHBDMAINLINKSTARTCHN]{AHB/AXI\_DMA\_INLINK\_START\_CH\regindex{n}} and \hyperref[fielddesc:AHBDMAOUTLINKSTARTCHN]{AHB/AXI\_DMA\_OUTLINK\_START\_CH\regindex{n}}.

For GDMA-AXI channels, set \hyperref[fielddesc:AXIDMAINCMDDISABLECHN]{AXI\_DMA\_IN\_CMD\_DISABLE\_CH\regindex{n}} or \hyperref[fielddesc:AXIDMAOUTCMDDISABLECHN]{AXI\_DMA\_OUT\_CMD\_DISABLE\_CH\regindex{n}} to pause data transfer on the corresponding channel.

Sometimes software must append more descriptors after a DMA transfer has already started. One approach is to clear the EOF bit of the last descriptor in the loaded list and set its next descriptor address pointer (DW2) to the first descriptor of the new list. This approach fails if the DMA transfer has already finished or is about to finish.

The GDMA controller provides dedicated logic so that a transfer can continue or restart. If the transfer is still in progress, the controller processes the appended descriptors. If the transfer has finished, the controller restarts with the new descriptors. This logic is implemented by the Restart function.

When using the Restart function, software updates the last descriptor in the loaded list so that DW2 points to the first descriptor of the new list. Software then sets \hyperref[fielddesc:AHBDMAINLINKRESTARTCHN]{AHB/AXI\_DMA\_INLINK\_RESTART\_CH\regindex{n}} or \hyperref[fielddesc:AHBDMAOUTLINKRESTARTCHN]{AHB/AXI\_DMA\_OUTLINK\_RESTART\_CH\regindex{n}} (hardware automatically clears these bits). As shown in Figure \ref{fig:gdma-link-restart}, when hardware reads the last descriptor in the loaded list, it obtains the address of the new list and continues processing it.

\begin{figure}[H]
\includegraphics[width=1\textwidth]{\modulefiles/figures/link_restart}
\centering
\caption{Relationship among Linked Lists}
\label{fig:gdma-link-restart}
\end{figure}


\subsection{Linked List Reading Process}

After software configures and starts GDMA, GDMA reads the linked list from memory and checks whether the descriptors are valid. A channel starts data transfer only when all descriptors pass the checks. If any descriptor fails a check, hardware triggers a descriptor error interrupt (AHB/AXI\_DMA\_IN\_DSCR\_ERR\_CH\regindex{n}\_INT or AHB/AXI\_DMA\_OUT\_DSCR\_ERR\_CH\regindex{n}\_INT), and the channel stops.

The descriptor checks include:
\begin{itemize}
    \item Owner bit check when \hyperref[fielddesc:AHBDMAINCHECKOWNERCHN]{AHB/AXI\_DMA\_IN\_CHECK\_OWNER\_CH\regindex{n}} or \hyperref[fielddesc:AHBDMAOUTCHECKOWNERCHN]{AHB/AXI\_DMA\_OUT\_CHECK\_OWNER\_CH\regindex{n}} is set to 1. If the owner bit is 0, the CPU owns the buffer and the check fails. If \hyperref[fielddesc:AHBDMAINCHECKOWNERCHN]{AHB/AXI\_DMA\_IN\_CHECK\_OWNER\_CH\regindex{n}} or \hyperref[fielddesc:AHBDMAOUTCHECKOWNERCHN]{AHB/AXI\_DMA\_OUT\_CHECK\_OWNER\_CH\regindex{n}} is 0, hardware does not check the owner bit.
    \item Descriptor address check: the descriptor must lie within the configured memory address space.
        \begin{itemize}
            \item GDMA-AHB: The descriptor address must be within \hyperref[fielddesc:AHBDMAACCESSINTRMEMSTARTADDR]{AHB\_DMA\_ACCESS\_INTR\_MEM\_START\_ADDR} \verb+~+ \hyperref[fielddesc:AHBDMAACCESSINTRMEMENDADDR]{AHB\_DMA\_ACCESS\_INTR\_MEM\_END\_ADDR}.
            \item GDMA-AXI: The descriptor address must be within \hyperref[fielddesc:AXIDMAACCESSINTRMEMSTARTADDR]{AXI\_DMA\_ACCESS\_INTR\_MEM\_START\_ADDR} \verb+~+ \hyperref[fielddesc:AXIDMAACCESSINTRMEMENDADDR]{AXI\_DMA\_ACCESS\_INTR\_MEM\_END\_ADDR}, or within \hyperref[fielddesc:AXIDMAACCESSEXTRMEMSTARTADDR]{AXI\_DMA\_ACCESS\_EXTR\_MEM\_START\_ADDR} \verb+~+ \hyperref[fielddesc:AXIDMAACCESSEXTRMEMENDADDR]{AXI\_DMA\_ACCESS\_EXTR\_MEM\_END\_ADDR}.
        \end{itemize}
        See Section \ref{sec:dma-access-inter-ram} for details.
\end{itemize}

After software detects a descriptor error interrupt, reset the corresponding channel and set \hyperref[fielddesc:AHBDMAOUTLINKSTARTCHN]{AHB/AXI\_DMA\_OUTLINK\_START\_CH\regindex{n}} or \hyperref[fielddesc:AHBDMAINLINKSTARTCHN]{AHB/AXI\_DMA\_INLINK\_START\_CH\regindex{n}} to restart GDMA.


\subsection{Interrupt Response Mechanism for GDMA-AXI Linked List Switching}

GDMA-AXI can generate an interrupt when linked list switching completes. Set \hyperref[fielddesc:AXIDMALINKSWITCHSTATECHN]{AXI\_DMA\_LINK\_SWITCH\_STATE\_CH\regindex{n}} to 1 to enable linked list switching. After switching succeeds, if AXI\_DMA\_OUT\_LINK\_SWITCH\_CH\regindex{n}\_INT is enabled, GDMA-AXI generates this interrupt and clears \hyperref[fielddesc:AXIDMALINKSWITCHSTATECHN]{AXI\_DMA\_LINK\_SWITCH\_STATE\_CH\regindex{n}}, indicating that the linked list has been switched.

This feature serves only as a status indication and does not affect normal GDMA-AXI data transfer.

\subsection{EOF}

{\bfseries Note:} In this chapter, EOF of transmit descriptors refers to suc\_eof (bit 30 of DW0); EOF of receive descriptors can be suc\_eof (bit 30 of DW0) or err\_eof (bit 28 of DW0).

GDMA uses end-of-frame (EOF) flags to indicate that the data segment corresponding to a descriptor has been transferred.

For data transmission, the GDMA generates two types of EOF interrupts:
\begin{itemize}
    \item AHB/AXI\_DMA\_OUT\_EOF\_CH\regindex{n}\_INT: Generated when any descriptor in the linked list has the suc\_eof flag set and the data corresponding to that descriptor has been transmitted. This interrupt is enabled by setting \hyperref[fielddesc:AHBDMAOUTEOFCHNINTENA]{AHB/AXI\_DMA\_OUT\_EOF\_CH\regindex{n}\_INT\_ENA}.
    \item AHB/AXI\_DMA\_OUT\_TOTAL\_EOF\_CH\regindex{n}\_INT: Generated when the last descriptor in the linked list has the suc\_eof flag set and the data corresponding to that descriptor has been transmitted. This interrupt is enabled by setting \hyperref[fielddesc:AHBDMAOUTTOTALEOFCHNINTENA]{AHB/AXI\_DMA\_OUT\_TOTAL\_EOF\_CH\regindex{n}\_INT\_ENA}.
\end{itemize}

For data reception, the GDMA also generates two types of EOF interrupts:
\begin{itemize}
    \item AHB/AXI\_DMA\_IN\_SUC\_EOF\_CH\regindex{n}\_INT: Generated when a data segment with an EOF flag has been received. This interrupt is enabled by setting \hyperref[fielddesc:AHBDMAINSUCEOFCHNINTENA]{AHB/AXI\_DMA\_IN\_SUC\_EOF\_CH\regindex{n}\_INT\_ENA}.
    \item (UHCI and PARLIO only) AHB/AXI\_DMA\_IN\_ERR\_EOF\_CH\regindex{n}\_INT: Generated when the data segment corresponding to a descriptor has been received but contains errors. This interrupt is enabled by setting the \hyperref[fielddesc:AHBDMAINERREOFCHNINTENA]{AHB/AXI\_DMA\_IN\_ERR\_EOF\_CH\regindex{n}\_INT\_ENA} bit, and is valid only when the channel is connected to UHCI or PARLIO.
\end{itemize}

When software detects an \hyperref[int:GDMAOUTTOTALEOFINT]{AHB/AXI\_DMA\_OUT\_TOTAL\_EOF\_CH\regindex{n}\_INT} or \hyperref[int:GDMAINSUCEOFINT]{AHB/AXI\_DMA\_IN\_SUC\_EOF\_CH\regindex{n}\_INT} interrupt, read \hyperref[fielddesc:AHBDMAOUTEOFDESADDRCHN]{AHB/AXI\_DMA\_OUT\_EOF\_DES\_ADDR\_CH\regindex{n}} or \hyperref[fielddesc:AHBDMAINSUCEOFDESADDRCHN]{AHB/AXI\_DMA\_IN\_SUC\_EOF\_DES\_ADDR\_CH\regindex{n}} to obtain the address of the descriptor whose transfer has completed. Software can then identify which descriptors have been used and reclaim them.

For RX, the descriptor address can also be recorded when an \hyperref[int:GDMAINERREOFINT]{AHB/AXI\_DMA\_IN\_ERR\_EOF\_CH\regindex{n}\_INT} interrupt is triggered, via \hyperref[fielddesc:AHBDMAINERREOFDESADDRCHN]{AHB/AXI\_DMA\_IN\_ERR\_EOF\_DES\_ADDR\_CH\regindex{n}}.

When \hyperref[fielddesc:AHBDMAINLINKAUTORETCHN]{AHB/AXI\_DMA\_INLINK\_AUTO\_RET\_CH\regindex{n}} is set, if the peripheral pushes data with the err\_eof flag to GDMA, GDMA returns to the start descriptor address of the current frame and repeats the receive transfer for that frame.


\subsection{Accessing Memory}\label{sec:dma-access-inter-ram}

The TX/RX channels of GDMA-AHB can access internal and external memory. The accessible address space is determined by \hyperref[fielddesc:AHBDMAACCESSINTRMEMSTARTADDR]{AHB\_DMA\_ACCESS\_INTR\_MEM\_START\_ADDR} \verb+~+ \hyperref[fielddesc:AHBDMAACCESSINTRMEMENDADDR]{AHB\_DMA\_ACCESS\_INTR\_MEM\_END\_ADDR}.

The TX/RX channels of GDMA-AXI can access:
\begin{itemize}
    \item Internal memory space configured by \hyperref[fielddesc:AXIDMAACCESSINTRMEMSTARTADDR]{AXI\_DMA\_ACCESS\_INTR\_MEM\_START\_ADDR} and \hyperref[fielddesc:AXIDMAACCESSINTRMEMENDADDR]{AXI\_DMA\_ACCESS\_INTR\_MEM\_END\_ADDR};
    \item External memory space configured by \hyperref[fielddesc:AXIDMAACCESSEXTRMEMSTARTADDR]{AXI\_DMA\_ACCESS\_EXTR\_MEM\_START\_ADDR} and \hyperref[fielddesc:AXIDMAACCESSEXTRMEMENDADDR]{AXI\_DMA\_ACCESS\_EXTR\_MEM\_END\_ADDR}.
\end{itemize}

To accelerate data transfer, GDMA supports burst transfer mode. For GDMA-AHB, burst transfer is disabled by default. Set \hyperref[fielddesc:AHBDMAINDSCRBURSTENCHN]{AHB\_DMA\_INDSCR\_BURST\_EN\_CH\regindex{n}} to enable burst transfer on RX channels, and set \hyperref[fielddesc:AHBDMAOUTDSCRBURSTENCHN]{AHB\_DMA\_OUTDSCR\_BURST\_EN\_CH\regindex{n}} to enable burst transfer on TX channels. Select the burst transfer mode via \hyperref[fielddesc:AHBDMAINDATABURSTMODESELCHN]{AHB\_DMA\_IN\_DATA\_BURST\_MODE\_SEL\_CH\regindex{n}} and \hyperref[fielddesc:AHBDMAOUTDATABURSTMODESELCHN]{AHB\_DMA\_OUT\_DATA\_BURST\_MODE\_SEL\_CH\regindex{n}}. The valid burst transfer modes are:
\begin{itemize}
    \item 0: SINGLE transfer (4 bytes)
    \item 1: INCR4 transfer (16 bytes)
    \item 2: INCR8 transfer (32 bytes)
    \item 3: INCR16 transfer (64 bytes)
\end{itemize}

For GDMA-AXI, burst transfer is enabled by default and cannot be disabled. Software can configure the amount of data transferred in each AXI burst via \hyperref[fielddesc:AXIDMAINBURSTSIZESELCHN]{AXI\_DMA\_IN\_BURST\_SIZE\_SEL\_CH\regindex{n}} and \hyperref[fielddesc:AXIDMAOUTBURSTSIZESELCHN]{AXI\_DMA\_OUT\_BURST\_SIZE\_SEL\_CH\regindex{n}}. Valid burst lengths are 8, 16, 32, 64, or 128 bytes.

When GDMA-AHB and GDMA-AXI access the configured internal memory and non-encrypted external memory space, there are no alignment requirements for linked list descriptor parameters.

When accessing the encrypted external memory space (see Chapter \ref{mod:extmemencr} \textit{\nameref{mod:extmemencr}}), the buffer address pointer and corresponding data must be 16-byte aligned; other parameters have no alignment requirements.

Note that encrypted external memory space cannot be accessed by GDMA-AHB-LP.


\subsection{Arbitration}

To ensure timely response to high-speed, low-latency peripherals such as SPI, GDMA implements channel priority arbitration and channel weight arbitration.

\begin{itemize}
    \item Priority arbitration: Each channel can be assigned a priority from 0 \verb+~+ 15. The larger the number, the higher the priority. If multiple channels request data transfer at the same time, GDMA responds to higher-priority channels first.
    \item Weight arbitration:
        \begin{itemize}
            \item Each channel is assigned a weight (token count) from 0 \verb+~+ 15. GDMA divides the bus (AHB/AXI) clock period into time slots. Within each time slot, each channel may perform as many transfer requests as its token count allows; each request consumes one token.

            If a channel exhausts its tokens within a time slot, GDMA stops responding to its requests until the slot ends or all channels exhaust their tokens. GDMA then refreshes token counts and starts the next time slot.
            \item If a channel has a non-zero token count, GDMA waits for all channels to exhaust their tokens within each time slot, even when some channels have no transfer requests. This wastes bandwidth when idle channels hold non-zero token counts.

            GDMA provides a weight arbitration optimization switch. When enabled, channels with no transfer requests are treated as having zero tokens and do not participate in arbitration. When no channel has transfer requests, the arbiter exits the current time slot early, improving response speed and transfer rate.
        \end{itemize}
\end{itemize}

Regardless of how channel priority is configured, descriptor transfers always have higher priority than data transfers. However, descriptor transfers are still subject to the weight arbitration. Once the configured tokens are exhausted, arbitration can only be requested again in the next time slot.

\begin{tiplisting}
\vspace{-2em}
\begin{itemize}
    \item If both priority and weight arbitration are enabled and priorities differ but weights are the same, higher-priority channels finish first when each channel transfers a small and equal amount of data.
    \item If both priority and weight differ and each channel transfers a large and equal amount of data, channels with larger weight receive more bandwidth and finish first.
\end{itemize}
\end{tiplisting}


\subsection{Bus Error Response Information Logging}\label{sec:dma-bus-error-resp}

During GDMA-AHB data transfer, if a slave on the bus returns an error response, the data transfer is not interrupted; GDMA-AHB continues to transfer data according to the existing linked list. As a result, the actual data received after transfer may not match the expected data. To facilitate troubleshooting, if an error response occurs during GDMA-AHB data transfer, the following internal registers record relevant transfer information:

\begin{itemize}
    \item \hyperref[fielddesc:AHBDMAAHBINFRESPERRADDR]{AHB\_DMA\_AHBINF\_RESP\_ERR\_ADDR}: Records the 32-bit address corresponding to the current bus transfer.
    \item \hyperref[fielddesc:AHBDMAAHBINFRESPERRCHID]{AHB\_DMA\_AHBINF\_RESP\_ERR\_CH\_ID}: Records the GDMA-AHB channel used for the current bus transfer.
    \item \hyperref[fielddesc:AHBDMAAHBINFRESPERRID]{AHB\_DMA\_AHBINF\_RESP\_ERR\_ID}: Records the transfer ID for the current peripheral-to-memory, memory-to-peripheral, or memory-to-memory transfer on the bus.
    \item \hyperref[fielddesc:AHBDMAAHBINFRESPERRWR]{AHB\_DMA\_AHBINF\_RESP\_ERR\_WR}: Records the type of transfer for the current bus transfer.
\end{itemize}

When GDMA-AHB initiates an AHB bus transfer as the master and receives an error response, it also generates an error response interrupt to notify the CPU. After the interrupt is generated, GDMA-AHB does not interrupt the data transfer.

In addition, GDMA-AHB does not latch register information for the first AHB bus transfer that triggers an error response. If multiple consecutive error response transfers occur, the error response logging registers are updated in real time; the registers retain information about the last AHB bus transfer that triggered an error response before the registers are read.

\subsection{Automatic Clock Gating}\label{sec:dma-auto-clk-gating}

When GDMA-AHB is operating, some scenarios require only part of the channels; in this case, clocks for unused channels can be disabled to reduce power consumption. Similarly, the internal arbitration and bus interface modules need to operate only during data transfer, and their clocks can be disabled during idle periods to save power. Currently, GDMA-AHB has the following internal modules:
\begin{itemize}
    \item Bus interface processing module
    \item Arbitration module
    \item RX data processing module
    \item RX descriptor processing module
    \item TX data processing module
    \item TX descriptor processing module
    \item Register configuration synchronization module
\end{itemize}

Clocks of the above modules are automatically disabled when idle to minimize power consumption. These clocks can also be forced on via register configuration. For example, setting \hyperref[fielddesc:AHBDMAAHBINFCLKEN]{AHB\_DMA\_AHBINF\_CLK\_EN} keeps the bus interface processing module clock always on; configurations for keeping other module clocks always on are similar.

\section{Event Task Matrix Feature}\label{sec:dma-etm-func}

The GDMA controller on \chipname{} supports the Event Task Matrix (ETM) function, which allows GDMA's ETM tasks to be triggered by any of the peripherals' ETM events, or GDMA's ETM events to trigger any of the peripherals' ETM tasks. This section introduces the ETM tasks and events related to GDMA. For more information, please refer to Chapter \ref{mod:evntaskmatrix} \nameref{mod:evntaskmatrix}.

GDMA can receive the following ETM tasks:

\begin{itemize}
    \item GDMA\_AHB/AXI\_TASK\_IN\_START\_CH\regindex{n}: When triggered, starts data transfer on GDMA receive channel \regindex{n}.
    \item GDMA\_AHB/AXI\_TASK\_OUT\_START\_CH\regindex{n}: When triggered, starts data transfer on GDMA transmit channel \regindex{n}.
\end{itemize}

\begin{tiplisting}
The above two ETM tasks provide the same functionality as setting \hyperref[fielddesc:AHBDMAINLINKSTARTCHN]{AHB/AXI\_DMA\_INLINK\_START\_CH\regindex{n}} and \\\hyperref[fielddesc:AHBDMAOUTLINKSTARTCHN]{AHB/AXI\_DMA\_OUTLINK\_START\_CH\regindex{n}} via the CPU.

When \hyperref[fielddesc:AHBDMAINETMENCHN]{AHB/AXI\_DMA\_IN\_ETM\_EN\_CH\regindex{n}} or \hyperref[fielddesc:AHBDMAOUTETMENCHN]{AHB/AXI\_DMA\_OUT\_ETM\_EN\_CH\regindex{n}} is 1, only ETM can start GDMA in the corresponding direction and channel. When \hyperref[fielddesc:AHBDMAINETMENCHN]{AHB/AXI\_DMA\_IN\_ETM\_EN\_CH\regindex{n}} or \hyperref[fielddesc:AHBDMAOUTETMENCHN]{AHB/AXI\_DMA\_OUT\_ETM\_EN\_CH\regindex{n}} is 0, only the CPU can enable the corresponding GDMA channel.
\end{tiplisting}

GDMA can generate the following ETM events:

\begin{itemize}
    \item GDMA\_AHB/AXI\_EVT\_IN\_DONE\_CH\regindex{n}: Indicates that data pointed to by a receive descriptor on channel \regindex{n} has been received.
    \item GDMA\_AHB/AXI\_EVT\_IN\_SUC\_EOF\_CH\regindex{n}: Indicates that data pointed to by a receive descriptor with EOF bit set to 1 on channel \regindex{n} has been received.
    \item GDMA\_AHB/AXI\_EVT\_IN\_FIFO\_EMPTY\_CH\regindex{n}: Indicates that the RX FIFO on channel \regindex{n} changed from non-empty to empty.
    \item GDMA\_AHB/AXI\_EVT\_IN\_FIFO\_FULL\_CH\regindex{n}: Indicates that the RX FIFO on channel \regindex{n} changed from non-full to full.
    \item GDMA\_AHB/AXI\_EVT\_OUT\_DONE\_CH\regindex{n}: Indicates that data pointed to by a transmit descriptor on channel \regindex{n} has been transmitted.
    \item GDMA\_AHB/AXI\_EVT\_OUT\_SUC\_EOF\_CH\regindex{n}: Indicates that data pointed to by a transmit descriptor with EOF bit set to 1 on channel \regindex{n} has been transmitted.
    \item GDMA\_AHB/AXI\_EVT\_OUT\_TOTAL\_EOF\_CH\regindex{n}: Indicates that data pointed to by the last transmit descriptor with EOF bit set to 1 on channel \regindex{n} has been transmitted.
    \item GDMA\_AHB/AXI\_EVT\_OUT\_FIFO\_EMPTY\_CH\regindex{n}: Indicates that the TX FIFO on channel \regindex{n} changed from non-empty to empty.
    \item GDMA\_AHB/AXI\_EVT\_OUT\_FIFO\_FULL\_CH\regindex{n}: Indicates that the TX FIFO on channel \regindex{n} changed from non-full to full.
\end{itemize}

In practical applications, GDMA's ETM events can trigger GDMA's own ETM tasks. For example, the GDMA\_AHB/AXI\_EVT\_OUT\_TOTAL\_EOF\_CH0 event can trigger the GDMA\_AHB/AXI\_TASK\_IN\_START\_CH1 task to start a new round of GDMA operations.

\section{Interrupts}

\chipname{}'s GDMA module can generate the following interrupt signals that will be sent to the \hyperref[mod:intmtrx]{Interrupt Matrix}.

    \begin{itemize}
        \item GDMA-AHB-HP:
            \begin{itemize}
                \item AHB\_PDMA\_IN/OUT\_CH0\_INTR
                \item AHB\_PDMA\_IN/OUT\_CH1\_INTR
                \item AHB\_PDMA\_IN/OUT\_CH2\_INTR
                \item AHB\_PDMA\_IN/OUT\_CH3\_INTR
                \item AHB\_PDMA\_IN/OUT\_CH4\_INTR
            \end{itemize}
        \item GDMA-AHB-LP:
            \begin{itemize}
                \item AHB\_PDMA\_IN/OUT\_CH0\_INTR
                \item AHB\_PDMA\_IN/OUT\_CH1\_INTR
            \end{itemize}
        \item GDMA-AXI:
            \begin{itemize}
                \item AXI\_PDMA\_IN/OUT\_CH0\_INTR
                \item AXI\_PDMA\_IN/OUT\_CH1\_INTR
                \item AXI\_PDMA\_IN/OUT\_CH2\_INTR
            \end{itemize}
    \end{itemize}

There are several internal interrupt sources from GDMA that can generate the above interrupt signals.

The AHB/AXI\_PDMA\_IN\_CH\regindex{n}\_INTR signals are generated by the following interrupt sources:

\begin{itemize}
    \item \label{int:GDMAINDONEINT}AHB/AXI\_DMA\_IN\_DONE\_CH\regindex{n}\_INT: For receive channel \textcolor{red}{\it{n}}, triggered when data corresponding to a receive descriptor has been received.
    \item \label{int:GDMAINSUCEOFINT}AHB/AXI\_DMA\_IN\_SUC\_EOF\_CH\regindex{n}\_INT: For receive channel \regindex{n}, triggered when data corresponding to a receive descriptor has been received and the descriptor's suc\_eof is 1.
    \item \label{int:GDMAINERREOFINT}AHB/AXI\_DMA\_IN\_ERR\_EOF\_CH\regindex{n}\_INT: For receive channel \textcolor{red}{\it{n}}, triggered when an error occurs in the data segment corresponding to a received descriptor. (This interrupt is valid only when the peripheral is UHCI or PARLIO.)
    \item \label{int:GDMAINDSCREMPTYINT}AHB/AXI\_DMA\_IN\_DSCR\_EMPTY\_CH\regindex{n}\_INT: For receive channel \textcolor{red}{\it{n}}, triggered when the buffer size pointed to by a receive descriptor is smaller than the length of data to be received.
    \item \label{int:GDMAINDSCRERRINT}AHB/AXI\_DMA\_IN\_DSCR\_ERR\_CH\regindex{n}\_INT: For receive channel \textcolor{red}{\it{n}}, triggered when a receive descriptor fails any descriptor check.
    \item \label{int:GDMAINFIFOOVFINT}AHB\_DMA\_INFIFO\_OVF\_CH\regindex{n}\_INT or AXI\_DMA\_INFIFO\_L1/L2/L3\_OVF\_CH\regindex{n}\_INT: Triggered when the GDMA-AHB receive buffer or GDMA-AXI receive L1, L2, or L3 buffer overflows.
    \item \label{int:GDMAINFIFOUDFINT}AHB/AXI\_DMA\_INFIFO\_UDF\_CH\regindex{n}\_INT or AXI\_DMA\_INFIFO\_L1/L2/L3\_UDF\_CH\regindex{n}\_INT: Triggered when the GDMA-AHB receive buffer or GDMA-AXI receive L1, L2, or L3 buffer has no data.
    \item \label{int:GDMAINAHBINFRESPERRINT}AHB\_DMA\_IN\_AHBINF\_RESP\_ERR\_CH\regindex{n}\_INT: Triggered when GDMA-AHB receive channel \textcolor{red}{\it{n}} performs a data transfer and an error response occurs on the AHB bus.
\end{itemize}

The AHB/AXI\_PDMA\_OUT\_CH\regindex{n}\_INTR signals are generated by the following interrupt sources:

\begin{itemize}
    \item \label{int:GDMAOUTDONEINT}AHB/AXI\_DMA\_OUT\_DONE\_CH\regindex{n}\_INT: For transmit channel \textcolor{red}{\it{n}}, triggered when data corresponding to a transmit descriptor has been sent.
    \item \label{int:GDMAOUTEOFINT}AHB/AXI\_DMA\_OUT\_EOF\_CH\regindex{n}\_INT: For transmit channel \textcolor{red}{\it{n}}, triggered when the EOF bit of a transmit descriptor is 1. The trigger timing depends on \hyperref[fielddesc:AHBDMAOUTEOFMODECHN]{AHB/AXI\_DMA\_OUT\_EOF\_MODE\_CH\regindex{n}}:
        \begin{itemize}
            \item When set to 0: triggered when the last byte of data corresponding to this descriptor enters the GDMA TX channel from the bus;
            \item When set to 1: triggered when the last byte of data corresponding to this descriptor leaves the GDMA TX channel.
        \end{itemize}
    \item \label{int:GDMAOUTDSCRERRINT}AHB/AXI\_DMA\_OUT\_DSCR\_ERR\_CH\regindex{n}\_INT: For transmit channel \textcolor{red}{\it{n}}, triggered when a transmit descriptor fails any descriptor check.
    \item \label{int:GDMAOUTTOTALEOFINT}AHB/AXI\_DMA\_OUT\_TOTAL\_EOF\_CH\regindex{n}\_INT: For transmit channel \textcolor{red}{\it{n}}, triggered when the last descriptor in the linked list has suc\_eof configured and the data corresponding to that descriptor has been transmitted.
    \item \label{int:GDMAOUTFIFOOVFINT}AHB\_DMA\_OUTFIFO\_OVF\_CH\regindex{n}\_INT or AXI\_DMA\_OUTFIFO\_L1/L2/L3\_OVF\_CH\regindex{n}\_INT: Triggered when the GDMA-AHB transmit buffer or GDMA-AXI transmit L1, L2, or L3 buffer overflows.
    \item \label{int:GDMAOUTFIFOUDFINT}AHB\_DMA\_OUTFIFO\_UDF\_CH\regindex{n}\_INT or AXI\_DMA\_OUTFIFO\_L1/L2/L3\_UDF\_CH\regindex{n}\_INT: Triggered when the GDMA-AHB transmit buffer or GDMA-AXI transmit L1, L2, or L3 buffer has no data.
    \item \label{int:AXIDMAOUTLINKSWITCHINT}AXI\_DMA\_OUT\_LINK\_SWITCH\_CH\regindex{n}\_INT: Triggered when GDMA-AXI transmit channel \regindex{n} switches from one linked list to the next.
    \item \label{int:GDMAOUTAHBINFRESPERRINT}AHB\_DMA\_OUT\_AHBINF\_RESP\_ERR\_CH\regindex{n}\_INT: Triggered when GDMA-AHB transmit channel \textcolor{red}{\it{n}} performs a data transfer and an error response occurs on the AHB bus.
\end{itemize}


\section{Programming Procedures}

Configure GDMA clock gating via \hyperref[fielddesc:HPSYSCLKRSTAHBPDMASYSCLKEN]{HP\_SYS\_CLKRST\_AHB/AXI\_PDMA\_SYS\_CLK\_EN}; clock gating is enabled by default. Reset GDMA by configuring \hyperref[fielddesc:HPSYSCLKRSTRSTENAHBPDMA]{HP\_SYS\_CLKRST\_RST\_EN\_AHB/AXI\_PDMA}.

\subsection{Programming Procedures for GDMA's Transmit Channel}

To transmit data using GDMA, configure the GDMA TX channel as follows:
\begin{enumerate}
    \item Set \hyperref[fielddesc:AHBDMAOUTRSTCHN]{AHB/AXI\_DMA\_OUT\_RST\_CH\regindex{n}} to 1 and then to 0 to reset the GDMA TX channel state machine and FIFO pointer.
    \item Load a transmit linked list and configure \hyperref[fielddesc:AHBDMAOUTLINKADDRCHN]{AHB/AXI\_DMA\_OUTLINK\_ADDR\_CH\regindex{n}} to point to the first transmit descriptor.
    \item Configure \hyperref[fielddesc:AHBDMAPERIOUTSELCHN]{AHB/AXI\_DMA\_PERI\_OUT\_SEL\_CH\regindex{n}} to the peripheral number, as shown in Table \ref{tab:gdma-ahb-hp-peri-sel}, Table \ref{tab:gdma-ahb-lp-peri-sel}, and Table \ref{tab:gdma-axi-peri-sel}.
    \item Set \hyperref[fielddesc:AHBDMAOUTLINKSTARTCHN]{AHB/AXI\_DMA\_OUTLINK\_START\_CH\regindex{n}} to start GDMA TX channel data transfer.
    \item Configure and enable the corresponding peripheral. See the corresponding peripheral chapter for details.
    \item Wait for the AHB/AXI\_DMA\_OUT\_TOTAL\_EOF\_CH\regindex{n}\_INT interrupt, which indicates that data transfer is complete.
\end{enumerate}

\subsection{Programming Procedures for GDMA's Receive Channel}
To receive data using GDMA, configure the GDMA RX channel as follows:
\begin{enumerate}
    \item Set \hyperref[fielddesc:AHBDMAINRSTCHN]{AHB/AXI\_DMA\_IN\_RST\_CH\regindex{n}} to 1 and then to 0 to reset the GDMA RX channel state machine and FIFO pointer.
    \item Load a receive linked list and configure \hyperref[fielddesc:AHBDMAINLINKADDRCHN]{AHB/AXI\_DMA\_INLINK\_ADDR\_CH\regindex{n}} to point to the first receive descriptor.
    \item Configure \hyperref[fielddesc:AHBDMAPERIINSELCHN]{AHB/AXI\_DMA\_PERI\_IN\_SEL\_CH\regindex{n}} to the peripheral number, as shown in Table \ref{tab:gdma-ahb-hp-peri-sel}, Table \ref{tab:gdma-ahb-lp-peri-sel}, and Table \ref{tab:gdma-axi-peri-sel}.
    \item Set \hyperref[fielddesc:AHBDMAINLINKSTARTCHN]{AHB/AXI\_DMA\_INLINK\_START\_CH\regindex{n}} to start GDMA RX channel data transfer.
    \item Configure and enable the corresponding peripheral. See the corresponding peripheral chapter for details.
\end{enumerate}

\subsection{Programming Procedures for Memory-to-Memory Transfer}
To transfer data from one memory location to another using GDMA, configure as follows:
\begin{enumerate}
    \item Set \hyperref[fielddesc:AHBDMAOUTRSTCHN]{AHB/AXI\_DMA\_OUT\_RST\_CH\regindex{n}} to 1 and then to 0 to reset the GDMA TX channel state machine and FIFO pointer.
    \item Set \hyperref[fielddesc:AHBDMAINRSTCHN]{AHB/AXI\_DMA\_IN\_RST\_CH\regindex{n}} to 1 and then to 0 to reset the GDMA RX channel state machine and FIFO pointer.
    \item Load a transmit linked list and configure \hyperref[fielddesc:AHBDMAOUTLINKADDRCHN]{AHB/AXI\_DMA\_OUTLINK\_ADDR\_CH\regindex{n}} to point to the first transmit descriptor.
    \item Load a receive linked list and configure \hyperref[fielddesc:AHBDMAINLINKADDRCHN]{AHB/AXI\_DMA\_INLINK\_ADDR\_CH\regindex{n}} to point to the first receive descriptor.
    \item Set \hyperref[fielddesc:AHBDMAMEMTRANSENCHN]{AHB/AXI\_DMA\_MEM\_TRANS\_EN\_CH\regindex{n}} to enable memory-to-memory transfer.
    \item Set \hyperref[fielddesc:AHBDMAOUTLINKSTARTCHN]{AHB/AXI\_DMA\_OUTLINK\_START\_CH\regindex{n}} to start GDMA TX channel data transfer.
    \item Set \hyperref[fielddesc:AHBDMAINLINKSTARTCHN]{AHB/AXI\_DMA\_INLINK\_START\_CH\regindex{n}} to start GDMA RX channel data transfer.
    \item If the suc\_eof bit is set in a transmit descriptor, an AHB/AXI\_DMA\_IN\_SUC\_EOF\_CH\regindex{n}\_INT interrupt is triggered when the data segment corresponding to that descriptor has been transmitted.
\end{enumerate}

\subsection{Programming Procedures for Channel Priority and Weight}

Priority arbitration can be configured as follows:
\begin{enumerate}
    \item Configure \hyperref[fielddesc:AHBDMATXPRICHN]{AHB/AXI\_DMA\_TX\_PRI\_CH\regindex{n}} and \hyperref[fielddesc:AHBDMARXPRICHN]{AHB/AXI\_DMA\_RX\_PRI\_CH\regindex{n}} as the priority for TX and RX channels.

\end{enumerate}

Weight arbitration can be configured as follows:
\begin{enumerate}
    \item Configure the weight arbitration time slot length:
        \begin{itemize}
            \item GDMA-AHB: Configure \hyperref[fielddesc:AHBDMAARBTIMEOUT]{AHB\_DMA\_ARB\_TIMEOUT}, which applies to both TX and RX directions;
            \item GDMA-AXI: Configure TX and RX directions independently via \hyperref[fielddesc:AXIDMAARBTIMEOUTTX]{AXI\_DMA\_ARB\_TIMEOUT\_TX} and \hyperref[fielddesc:AXIDMAARBTIMEOUTRX]{AXI\_DMA\_ARB\_TIMEOUT\_RX}.
        \end{itemize}
    \item Configure \hyperref[fielddesc:AHBDMATXCHARBWEIGHCHN]{AHB/AXI\_DMA\_TX\_CH\_ARB\_WEIGH\_CH\regindex{n}} and \hyperref[fielddesc:AHBDMARXCHARBWEIGHCHN]{AHB/AXI\_DMA\_RX\_CH\_ARB\_WEIGH\_CH\regindex{n}} as the token count for each channel.
    \item Clear \hyperref[fielddesc:AHBDMATXARBWEIGHOPTDIRCHN]{AHB/AXI\_DMA\_TX\_ARB\_WEIGH\_OPT\_DIR\_CH\regindex{n}} and \hyperref[fielddesc:AHBDMARXARBWEIGHOPTDIRCHN]{AHB/AXI\_DMA\_RX\_ARB\_WEIGH\_OPT\_DIR\_CH\regindex{n}} to enable weight arbitration optimization for TX and RX directions.
    \item Enable weight arbitration:
        \begin{itemize}
            \item GDMA-AHB: Set \hyperref[fielddesc:AHBDMAWEIGHTEN]{AHB\_DMA\_WEIGHT\_EN} to enable both TX and RX directions;
            \item GDMA-AXI: Set \hyperref[fielddesc:AXIDMAWEIGHTENTX]{AXI\_DMA\_WEIGHT\_EN\_TX} and \hyperref[fielddesc:AXIDMAWEIGHTENRX]{AXI\_DMA\_WEIGHT\_EN\_RX} to enable TX and RX directions respectively.
        \end{itemize}
\end{enumerate}
